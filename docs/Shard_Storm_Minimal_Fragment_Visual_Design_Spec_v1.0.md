# Shard Storm — Minimal Fragment Visual Design Specification

- 문서 버전: v1.0
- 기준: M16 구현 브랜치 feat/m12-m16-destruction-evolution
- 문서 성격: **시각 디자인 전용 명세**
- 적용 대상: 핵심 전투 필드 / 도형 / 파편 / 파괴 VFX / 전투 HUD / 화면 연출 / 접근성 / 제작 가이드
- 상태: 디자인 제안. 구현·밸런스 변경을 승인하는 문서가 아님

> **한 줄 아트 디렉션:** 어두운 평면 위에 소수의 선명한 기하학 도형을 배치하고, 도형이 깨지는 순간만 날카로운 파편·짧은 빛·시간차 파동으로 강조한다.

## 1. 범위와 기존 기획과의 관계

기존 M1~M16 기획서가 게임 규칙, 월드, 도형 능력, 성장, 경제, 보상, 타이머를 정의한다. **이 문서는 그 내용을 재정의하지 않는다.** 특히 새로운 무기, 스킬, 도형 능력, 연쇄 조건, 자원, 난이도, 전투 시간은 제안하지 않는다.

이번 문서의 유일한 목적은 기존 파괴 결과를 **어떤 모양·색·빛·움직임으로 전달할지** 정하는 것이다. 시각 변경은 충돌 판정, 파편 실제 궤도, 이벤트 처리 순서, RNG, 보상, 저장 데이터에 영향을 주면 안 된다.

### 반드시 지킬 비주얼 제약

- 플레이어 캐릭터, 우주선, 총, 포탑, 중앙 발사 오브젝트 **없음**.
- 도형이 클릭의 대상이다. 파편은 **파괴된 도형에서** 나오는 것으로 보여야 한다.
- 모든 도형 사이를 잇는 상시 레이저·전기 빔·직선 연결선 **없음**. 전파가 실제 일어날 때만 가시화한다.
- 전투 필드는 기하학 도형을 가장 먼저 인식할 수 있어야 한다. 우주 풍경, 3D 결정체, 화려한 배경은 시선을 빼앗지 않는다.
- M16의 19종 도형, Modifier·Trait, Elite, Boss를 알아볼 수 있어야 한다. 실제 실루엣과 판정의 괴리를 키우지 않는다.

## 2. 최종 권장 컨셉 — Minimal Fragment

### 2.1 레퍼런스에서 가져올 원칙

- **Get Rid Of Those Corners:** 평면 기하학, 낮은 장식 밀도, 도형을 부수는 행위 자체가 화면의 핵심.
- **Nodebuster:** 짧은 반응 주기, 명확한 정보 계층, 성장에 따른 시각적 리듬.

원작의 스크린샷, 고유 UI, 아이콘 또는 에셋을 복제하지 않는다.

### 2.2 스타일 후보 비교

| 스타일 | 살아 있는 도형 | 파괴 순간 | 장점 | 판단 |
|---|---|---|---|---|
| **A. Clean Outline** | 얇은 외곽선 + 낮은 투명도 면 | 각진 파편 + 작은 히트 링 | 가장 높은 가독성·낮은 제작비 | **기본안** |
| **B. Flat Solid** | 무광 단색 면 + 명확한 테두리 | 같은 색 면 조각이 쪼개짐 | 타격 시 부피감, 모바일 가독성 | A/B 검증안 |
| **C. Crisp Pixel** | 제한 팔레트의 픽셀 도형 | 각진 픽셀 조각 / 블록 디졸브 | 인디 개성, 제작 규칙 명확 | 별도 스타일 실험안 |

서로 다른 스타일을 한 전투 장면에 혼합하지 않는다. 먼저 Clean Outline을 기준으로 제작하고, Flat Solid·Crisp Pixel은 동일 전투 기록에 외형만 교체해 비교한다.

### 2.3 화면의 밀도 원칙

- **평상시:** 도형과 HUD만 인지된다.
- **클릭 직후:** 맞은 도형과 클릭 지점이 단독으로 강조된다.
- **연쇄 진행:** 실제 파편이 지나간 경로·다음 충돌 지점이 순서대로 강조된다.
- **대형 연쇄:** 화면 전체 밝기를 올리는 대신 파괴 지점별 짧은 피크와 Chain HUD 강화로 규모를 전달한다.
- **연쇄 종료:** 잔상이 빠르게 정리되어 다음 클릭할 도형을 즉시 고를 수 있다.

## 3. 컬러 / 선 / 형태 디자인 토큰

### 3.1 기본 팔레트 (초안)

| 토큰 | HEX | 용도 |
|---|---|---|
| Background | #0B1020 | 메인 전투 배경 |
| Background Deep | #070A12 | 배경 변형·대비용 |
| Grid | #233047 | 옵션형 보조 격자 |
| Primary Energy | #61E8E1 | 클릭 피드백·핵심 파편 하이라이트 |
| Cascade | #8D80FF | 연쇄 관련 이펙트 보조 |
| Warm Highlight | #F6C46D | 높은 주목도·강조 |
| Danger | #FF6B83 | 경계·위험 표시 |
| Text Main | #DAE5F2 | 숫자·HUD |
| Text Subtle | #8C9AB1 | 보조 라벨 |

**주의:** 색상 토큰은 시각 가이드다. 기존 M16 도형 타입별 실제 색상/의미를 재지정하지 않는다. 형상 또는 색에 게임 규칙을 새로 연결하지 않는다. 특수 도형은 색뿐 아니라 실루엣·문양·테두리 차이로 구분한다.

### 3.2 두께·광량 기본안

아래 수치는 **960×540 논리 화면을 가정한 초기 시안 값**이며 gameplay 상수나 최종 자산 크기가 아니다.

- 기본 외곽선: 약 2~3 logical px. 작은 도형은 선이 끊어지지 않게 보정.
- 내부 면: 외곽선 색의 약 8~18% alpha. 가독성이 낮으면 면을 제거.
- 강조 외곽선: 평시보다 약 1.3~1.6배, 0.15초 이하의 짧은 피크.
- 외곽 glow: 평시 최소, 명중·파괴 시에만 짧게 사용. 외곽보다 넓은 과도한 halo 금지.
- 그리드: 유저 옵션이며 도형보다 충분히 어둡게; 간격이 공격 유도·판정 정보를 잘못 암시하지 않도록 함.
- 배경 장식: 정지·저대비 원칙. 대형 행성, 소행성 장애물, 전투에 없는 타깃 형태 금지.

## 4. 도형 19종 공통 렌더링 규칙

새로운 실루엣을 임의로 발명하기보다 기존 M16 shape definitions와 shape-outline.js의 실제 외곽선·회전·손상 형태를 **Source of Truth**로 사용한다.

### 공통 외형 레이어 (안쪽 → 바깥쪽)

1. 낮은 투명도의 면 또는 빈 면
2. 실제 shape polygon 외곽선
3. 필요 시 도형 고유 내부 기호·패턴
4. 손상 상태에 따른 균열/깎인 모서리
5. 기존 Modifier/Trait 식별 배지·보조 윤곽
6. Elite/Boss의 우선순위가 높은 식별층
7. 생성 시 순차 외곽선 드로잉

외곽선의 변형과 손상 단계는 기존 규칙을 따른다. 도형을 전혀 다른 크기의 3D 광물로 바꾸어 클릭 판정과 비주얼 크기가 어긋나게 하지 않는다.

### 구분 우선순위

- **1차:** 외곽 실루엣
- **2차:** 내부 패턴/마커
- **3차:** 색과 명도
- **4차:** 살아 있는 동안의 낮은 진폭 모션

Modifier/Trait·Elite·Boss가 중복될 때는 중요한 것을 더 굵게 그리는 방식만 반복하지 않는다. 외곽 이중선 / 내부 배지 / 코너 표시 등 **서로 다른 위치의 채널**을 사용한다.

## 5. 파괴·파편·연쇄 VFX 문법

이 문서에서 **게임플레이 파편**은 실제 충돌을 일으키는 shard를 뜻하며, **장식 파편**은 오직 시각적 분해 효과다. 두 종류를 혼동하지 않도록 외형을 구분한다.

| 요소 | 보이는 형태 | 움직임 | 금지 사항 |
|---|---|---|---|
| 직접 타격 | 짧은 흰색/민트 플래시·작은 링 | 클릭 위치 중심으로 빠르게 소멸 | 도형이 아닌 중앙 무기 발사 표현 |
| 부분 손상 | 모서리 균열·조각 2~4개 느낌 | 짧은 비행·즉시 소멸 | 실제 피해량과 불일치하는 대형 폭발 |
| 도형 파괴 | 외곽선 분리·면 균열 | 중심에서 도형 색상의 삼각/사각 조각이 퍼짐 | 뭉개진 연기·화염 구름 |
| **게임플레이 파편** | 읽기 쉬운 주 조각/뾰족한 팁 | 실제 계산된 위치·방향·반사만 표시 | 가짜 유도 궤적·없는 타격 연출 |
| 장식 파편 | 작고 흐린 면 조각 | 짧은 확산 후 페이드 | 실제 shard처럼 높은 시인성·긴 트레일 |
| 파편 명중 | 작은 접촉 플래시 | 실제 충돌 지점 단발 | 사전 타격 또는 조작된 다음 타깃 표시 |
| 범위 파동 | 얇은 확장 원형 테두리 | **실제 전파 시점**과 일치 | 범위 내 전체 즉시 피해처럼 보이기 |
| Chain 강조 | HUD 숫자 팝/짧은 색상 변화 | 실제 Chain 기준의 단계적 반응 | 화면 전체 지속적 섬광 |

### 5.1 파괴의 시각적 시퀀스

아래 단계는 **연출의 우선순위**이고 실제 효과 발생 시간을 강제하지 않는다.

1. 클릭 성공 → 클릭 지점 미세 충격 링 + 대상 플래시.
2. HP가 남음 → 작은 균열과 면 조각; 살아 있는 외곽선 유지.
3. 실제 파괴 확정 → 도형 외곽선이 끊기며 도형 재질을 닮은 파편 분출.
4. 생성된 게임플레이 shard가 실제 trajectory를 따라 이동.
5. 다음 도형에 접촉 → 해당 지점에 매우 짧은 히트 표시.
6. 후속 도형이 실제로 파괴되면 새로운 파편 분출 → 시간차 누적.
7. 남은 장식 입자는 빠르게 사라져 필드 가독성을 회복.

**시각적 연쇄 연결선/점선 화살표는 기본 전투 화면에서 사용하지 않는다.** 설명·디버그·튜토리얼 모드에서만 실제 경로 기반으로 선택적으로 사용한다.

### 5.2 파편 형태 제안

- 사각형 계열 파괴: 작고 뾰족한 사다리꼴/삼각형의 혼합.
- 삼각형 계열 파괴: 길고 가느다란 쐐기 형태.
- 별형·다각형 계열 파괴: 고유 꼭짓점 각도를 반영한 조각.
- 주 shard: 장식 조각보다 큰 형태와 명확한 앞 방향.
- 반사: 기존 로직이 실제 반사를 생성한 순간에만 짧은 방향 전환 플래시.

이는 **그림의 형태 제안**이며 생성 개수·각도·피해·사거리 변경 지시가 아니다.

## 6. Chain / Storm Stage 시각적 차등

M16의 Shatter → Cascade → Overload → Storm **4단계**는 게임 상태를 그대로 받아서 표현한다.

| 단계 | 배경·도형 | 효과 강도 | HUD |
|---|---|---|---|
| Shatter | 평상시 어두운 필드, 최소 glow | 기본 파편 가시성 확보 | 기본 체계 |
| Cascade | 명중 때만 조금 더 선명한 잔상 | 시간차 충돌 지점 강조 | Chain 수치 짧게 팝 |
| Overload | 연쇄 분출 중 조각의 명암 대비 강화 | 대형 파괴와 보스 이벤트를 우선 표시 | 이벤트 순간 강조 |
| Storm | 공격 결과가 가장 넓게 보이는 단계 | 전체 화면 발광이 아니라 **파괴 지점 단위** 강조 | 한 번의 뚜렷한 피크 후 정리 |

실제 단계 진입·Chain 10/20 이벤트에 대응하고, 별도의 새 단계나 타이밍을 만들지 않는다.

## 7. 전투 HUD 디자인

### 정보 위계

- 좌상단: 남은 시간
- 상단 중앙: Chain 및 Storm Stage의 간결한 진행 표시
- 우상단: 점수/획득량 등 현행 게임이 실제 표시하는 핵심 지표
- World/Boss 정보: 필요 시 작고 좁은 보조 줄
- DEV/QA 지표: 일반 플레이에서는 접거나 숨김

기본 화면은 **전투 필드가 우세한 풀캔버스**로 디자인한다. 하단에 스킬 슬롯/무기 장착창/체력 바/미니맵을 새로 만들지 않는다. 현재 표시해야 할 정보가 많은 경우에도 화면 위쪽의 짧은 라벨과 숫자부터 사용한다.

### 타이포그래피

- 숫자: 고대비 산세리프/모노스페이스 계열, tabular numerals 권장.
- 텍스트: 짧고 기능적인 라벨; 평시 과도한 대문자 장식·네온 장식 폰트 금지.
- Chain 강조: 글자 크기의 짧은 팝 + 색상 변화; 뒤에 큰 반투명 배너를 장시간 표시하지 않는다.
- 작은 창: 정보 간격을 줄이되 타깃 영역을 침범하지 않게 HUD 레이아웃 변경.

## 8. Boss / Elite / World별 시각 차이

### Boss / Elite

- 기존 도형의 실루엣과 핵심 약점·방어 상태를 먼저 식별할 수 있어야 한다.
- Boss는 외곽선의 **규모, 반복 패턴, 별도 게이트 표시**로 구분한다.
- 보호 중/취약 중 상태는 색만 바꾸지 않고 윤곽·아이콘·애니메이션 차이를 만든다.
- 보호된 Boss 타격에 성공 타격과 동일한 파괴 VFX를 쓰지 않는다.
- 보스의 여러 파츠가 있으면 각 파츠의 실제 판정 위치를 정확히 드러낸다.
- 전투 중 거대한 보스 캐릭터나 중앙 우주선을 도입하지 않는다.

### 월드 테마

월드별 차이는 **색 보조 팔레트 / 배경 그리드·노이즈 농도 / 점 형태 파티클 / HUD 작은 장식**에 한정해 시작한다. 현재 구현된 5 World 테마를 읽고 일관된 매핑표를 정하되, 월드별로 전투 화면 구성을 크게 바꾸지 않는다.

## 9. 접근성 / 이펙트 품질 단계

| 옵션 | Full | Reduced FX | Reduced Motion |
|---|---|---|---|
| 도형 외곽선 | 유지 | 유지 | 유지 |
| 실제 파편/파동의 위치 전달 | 유지 | **반드시 유지** | **반드시 유지** |
| 장식 파편 | 기본 상한 | 감소 | 감소 |
| Glow / 잔상 | 짧게 사용 | 대폭 감소 | 제거 가능 |
| 화면 흔들림 | 기존 안전 범위 내 | 최소/끔 | 끔 |
| 클릭/파괴 상태 구분 | 유지 | 유지 | 유지 |

Color-only coding 금지. 색각 접근성용 대체 팔레트, 흔들림 OFF, 광량 제한, 시야를 덮는 백색 프레임 금지. 실제 효과를 끄는 옵션은 게임 로직을 변경하지 않는다.

## 10. Godot 제작/유지보수 전달 기준 (비기능 시각 구현)

Godot로 옮길 때 **visual layer의 설계**에만 적용한다.

- Shape visuals: M16 geometry data에서 생성된 폴리곤 외곽/내부 채우기. 임의의 스프라이트로 모든 형상을 대체하지 않는다.
- Shard visuals: simulation이 제공한 현재 위치·각도·상태를 그대로 렌더.
- VFX visuals: 게임 이벤트를 수신해 장식만 생성. 전투 로직을 되돌려 호출하지 않음.
- 공통 Visual Token, Shape Style, Hit FX, Break FX, Wave FX를 데이터/Theme로 관리.
- 기존 M16의 장식 RNG와 전투 RNG 분리 원칙 유지.
- 효과 재사용·풀링 또는 배치 드로잉을 고려하되, Godot 실제 성능을 측정해 선택.
- 배경 렌더링은 게임 규칙과 완전히 독립.
- Web Compatibility 환경에서 Shader 없이도 의미가 전달되는 flat fallback 필수.

### 시각 에셋 제작 순서

1. **Clean Outline**의 기본 도형/외곽/손상 1개 세트.
2. 클릭 성공·부분 손상·실제 파괴의 3가지 구분.
3. 게임플레이 shard와 장식 조각의 다른 표현.
4. 파동/연쇄 단계 가독성.
5. 19종 전체 형태 + Modifier/Trait + Elite/Boss.
6. HUD/반응형/접근성 preset.
7. Flat Solid / Crisp Pixel 변형의 저비용 스타일 비교.

## 11. 화면 시안 수락 기준

동일한 실제 전투 리플레이/시드·기록을 기준으로 다음 프레임을 포착하여 비교한다.

1. **평상시:** 도형 실루엣이 1초 이내에 구분 가능한가?
2. **직접 명중:** 클릭 성공한 정확한 대상이 식별되는가?
3. **부분 손상:** 미파괴 도형과 파괴 도형이 구분되는가?
4. **최초 파괴:** 파편이 도형 자체에서 출발한 것으로 보이는가?
5. **연쇄 2~4회:** 가까운/먼 도형의 후속 충돌 순서를 읽을 수 있는가?
6. **Chain 10/20:** 시각적으로 커졌지만 조준 대상은 여전히 보이는가?
7. **Boss 보호/취약:** 다른 피드백으로 상태 차이가 드러나는가?
8. **19종 식별:** 주요 실루엣이 서로 구분되는가?
9. **FX OFF / Reduced Motion:** 게임 상태 정보가 사라지지 않는가?
10. **좁은 창 / FHD:** HUD가 실제 클릭 대상을 가리지 않는가?

M16의 외형 ON/OFF 비교와 보상·저장·RNG 회귀 기준을 유지한다. 시각 디자인의 성공은 장식 입자 수가 아니라 **대상 식별, 충돌 이해, 파편 방향 인지, 눈의 피로 감소, 파괴 만족감**으로 판단한다.
