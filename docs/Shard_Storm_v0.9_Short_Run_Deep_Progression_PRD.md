## 0. 변경 요청 배경과 제품 목표

### 사용자 플레이 피드백 (실제 요구)

- v0.8의 **클릭·파괴감각은 충분히 만족**스럽다. 이미 잘 동작하는 직접 클릭·콤보·순차 폭발을 새로 만들거나 크게 변경하지 말 것.
- 문제는 **성장이 너무 빠르고, 업그레이드와 새로운 콘텐츠가 너무 빨리 소진**된다는 것이다.
- **60초는 체감상 길다. 신규 기본 Run은 20초**로 변경한다.
- 화면 도형이 **조금씩 회전하고, 느리게 드리프트/유영**해서 동적인 느낌을 만든다.
- 참고작 `Space Rock Breaker`의 **원석/희귀 재료 → 별도 정산 → 분기형 능력 강화 → 새로운 재료·콘텐츠 해금** 구조를 Shard Storm에 적용한다. 총기·우주선·우주 배경의 외형을 그대로 복사하지 않는다.
- 최우선 목표는 **3~5회 플레이 후 끝나는 성장 구조를 개선하고, 20초 Run을 반복할 이유를 만드는 것**이다. 외형 확대보다 경제/콘텐츠 깊이 우선.

### 현재 v0.8 측정값 (자동 입력, 사람 플레이 아님)

`docs/Shard_Storm_v0.8_Balance_Report.md`에 따르면 기본 60초의 5시드 중앙값은 **695 파괴, 13,466 Photon, 연쇄 비율 72.4%**(Modifier ON). 기존 가격에선 **첫 자동 Run 후 총 35 레벨 전부 구매 가능**, ×6 가격 샌드박스도 5번째 Run에 모두 소진된다. 60초 동안 다량 보상이 발생하는 지금의 경제에서는 단순 가격 배율 변경만으로 콘텐츠가 오래 지속되지 않는다.

**v0.9의 답은 세 개의 루프**로 나눈다.

1. **20초 전투 루프:** 커서 직접 파괴 → 순차 파편 연쇄 → 원석(Raw) 획득.
2. **짧은 정산 루프:** 수집한 원석을 `Shard Refinery`에서 가공 → 제한적인 변동 보너스를 거쳐 Photon 정산.
3. **장기 해금 루프:** Photon 소비 + 누적 기록/희귀 촉매 조건 → 새로운 스킬 분기·원석 등급·대형 도형 해금 → 재도전.

참고작의 **구조적 보상 층**을 차용하되, 20초짜리 게임보다 정산이 길어지지 않게 한다.

### 중요한 해석

- **20초는 Run 전체에 공유하는 타이머 한 개다.** 내부 단계마다 20초를 다시 주지 않는다.
- Run 종료 조건은 **시간 0**. 모든 도형 파괴/보스 격파가 강제 종료 조건이 아니다.
- 단계 해금은 **동일 Run 내 누적 파괴 수**를 기준으로 한다. 이전 단계 도형이 살아 있어도 새로운 도형이 차츰 섞여 등장한다.
- `Extra Time`은 새로운 규칙에서 20/22/24/26/28/30/32초다. 이미 구매한 Lv은 유지하고 효용만 새 규칙으로 표시한다. 기존 구매자가 원하면 **1회 선택적 시간 스킬 재분배**를 제공하되 자동 초기화 금지.
- v0.8의 11개 스킬/재화/세이브를 **강제로 삭제하지 않는다.** 다만 기존 계정이 이미 올맥스이면 새 중장기 콘텐츠와 분리된 **격리 Fresh Lab 프로필**로 신규 유저 성장 밸런스를 재현한다.
- 실험 모드/테스트 광자 지급/테스트 구매는 사용자 실세이브에 영향을 주면 안 된다.

## 3. 도형 회전 + 미세 이동 (정식 물리 엔진 없이)

### 3.1 목표

도형이 공중에 가만히 고정된 것처럼 보이지 않게 하되, **플레이어가 클릭하려는 대상이 도망치거나 조준 난도가 지나치게 높아져선 안 된다.** 물리충돌/밀림은 여전히 장식 중심, 실제 위치는 **저속으로 유한 범위 내 이동**한다.

### 3.2 기본 Motion Profile

| 요소 | 제안 초기값 |
|---|---|
| 앵커 위치 | 현재 생성 시점의 안전한 `anchorX/anchorY` |
| 회전 | 도형마다 ±10~35도/초 (Star ±6~18도/초) |
| 드리프트 진폭 | 중심 기준 최대 6px (Star 최대 4px) |
| 드리프트 주기 | 약 3~6초, 도형별 위상 서로 다름 |
| 최대 순간 이동속도 | 약 16px/초 (디버그 기록) |
| 프로필 | Rotate only 35%, Drift only 25%, Both 30%, Static 10% |
| 가장자리 처리 | 앵커 기준 경계 안으로 진폭 포함 Clamp, 텔레포트/반사 없음 |
| 처음 튜토리얼 4도형 | 첫 안내 클릭 또는 최소 1초 동안 **위치·발사 방향 고정** |
| Cracked/Charged/Enhanced | 동일 규칙, 배지·균열·링은 항상 도형과 같이 이동/회전 |
| 시간 기준 | 게임 `simulationTime`; 일시정지 시 움직임도 정지 |

프로필은 **도형 생성 시 결정**한다. `motionSeed`를 도형 ID와 게임 시드로 도출하고 코스메틱 RNG와 분리한다. 같은 seed/설정의 Run을 재현할 수 있어야 한다.

제안 위치 식(개념):

- `worldX(t)=anchorX + ampX * (sin(phaseX + speedX*t) - sin(phaseX))`
- `worldY(t)=anchorY + ampY * (sin(phaseY + speedY*t) - sin(phaseY))`
- `worldAngle(t)=spawnAngle + rotationRate*t`

초기 `t=0`에 생성 앵커 위치와 일치하게 한다. 충격파 시각적 넉백은 별도 render offset으로 유지하고 **world collision 위치로 중복 적용하지 않는다**.

### 3.3 클릭/파편/충격파와 위치 일치 — 핵심 기술 제약

**화면에서 도형만 움직이고 충돌·클릭 중심은 생성 좌표에 고정시키는 구현 금지.**

기존 v0.8은 `game.js`의 Wave가 생성될 때 도형의 **고정된 위치로 예정 hit time을 예약(`registerWaveTarget`)**하는 방식이고, 파편도 `traceShard`가 고정 대상 중심을 사용한다. 실제 이동을 넣으면 **파동이 보이는 대상에 닿지 않았는데 피해가 나거나, 파편이 시각적 도형을 통과하는** 회귀가 발생할 수 있다.

필수 해결:

1. 도형의 `x/y`는 실제 현재 월드 좌표, `anchorX/Y`는 기준 좌표. 클릭과 렌더는 동일한 최신 월드 위치를 사용한다.
2. 파편은 고속 선분 충돌을 유지하되 **대상의 전/후 위치를 반영하는 상대 이동 스윕(continuous collision)** 또는 시간 분할/정확한 교차 시간 계산을 적용한다. 단순 그리드 한 틱 검사로 빠른 파편 누락 금지.
3. **파동은 고정된 미래 hit 시각을 일괄 예약하지 않는다.** 이동 대상에 대해 매 틱 파동 반경의 전/후 위치와 대상의 전/후 위치를 비교하여 최초 접촉 시점(필요하면 보간·이분 탐색)을 계산하고 이벤트 큐에 등록한다.
4. 이동 중 파동 앞에 들어온 도형은 외곽이 실제로 만난 경우에만 1회 피해; 파동이 이미 지나간 안쪽으로 늦게 진입한 대상은 재타격하지 않는다.
5. 시간 0 초과 사건, Spawn Grace(0.15s), `wave.hitIds`, `registeredIds`, EventId 순서, Chain 귀속, 중복 보상은 유지한다.
6. 충돌 대상을 찾을 때 중복 안전 영역/앵커 드리프트 때문에 도형이 겹치지 않도록 **앵커 배치 최소간격에 drift 여유 2×진폭**을 포함하거나 이동을 제한한다.
7. 시뮬레이션 60fps 고정틱과 가시 프레임 지연/일시정지 처리, 기존 cap 모두 유지. `motionEnabled` OFF 비교 토글과 동일 시드/동일 목표 좌표 정책 기록.
8. Triangle의 3방향 파편은 **파괴 순간 worldAngle**을 따른다. 안내 도형은 첫 입력까진 angle 유지해 4연쇄를 보장한다. Pentagon도 동일.
9. 움직이는 목표를 직접 커서로 따라가야 하므로 플레이어가 홀드/드래그 중 대상을 자연스럽게 공격할 수 있어야 한다. 직접 공격 범위는 불필요하게 축소하지 않는다.
10. 가능하면 **Motion OFF에서는 v0.8 고정대상 최적 경로**를 그대로 사용해 A/B 비교. Motion ON에서만 동적 접촉 처리, 단일 applyDamage 경로 공유.

### 3.4 모션 검수 기준

- 화면에 보이는 도형 중심과 클릭 판정 중심의 차이는 2px 이하(물리 기준, 의도적 시각 recoil 제외).
- 정상 Run에서 초당 각도·중심 이동은 매끄럽고 떨림·텔레포트 없음.
- 커서 1회 클릭에서 움직이는 도형을 성공 타격할 때 방금 보인 중심을 맞힐 수 있음.
- 이동 중 두 도형 충돌/겹침이 급증하지 않음.
- Triangle 최초 튜토리얼 클릭에서 기존 최소4 킬 시나리오 유지.
- 정적/동적 파동 1회 타격, 먼저 닿은 것부터 피해, 0초 이후 추가 보상 없음.
- 여러 시드 자동/브라우저 테스트에서 파편 통과/유령 피해가 관측되지 않아야 한다.

## 5. P0 재화 정산 재설계 — Raw Shards → Shard Refinery → Photon

### 5.1 두 재화의 역할

- `Raw Shards`: **한 Run 안에서 HP 제거량 + 완전 파괴 보너스**로 발생하는 원재료. 현행 `Game.runEarned` 계산 로직을 **원재료 점수**로 재명명/래핑해 재사용한다. 전투 중 이것은 곧바로 은행 Photon이 아니다.
- `Photon`: Run이 종료되고 Refinery 결과가 확정된 **영구 업그레이드 재화**. 기존 `save.bank` 보유분은 Photon으로 그대로 보존한다.
- 희귀 촉매(`Catalyst Fragments`)는 향후 신규 분기 해금용 **비거래성 획득 자원**(§7, P1). 첫 P0에서는 필드를 미래 호환되게만 설계해도 된다.

### 5.2 기본 변환과 전투 수익 감속

v0.8의 초당 Photon에 비해 구매가 과도하게 빨랐으므로, 다음 시작 프리셋을 제안한다.

`basePhoton = floor(rawShards * conversionRate)`

- `conversionRate = 0.06`(초기 제안값, 데이터로 변경 가능).
- **Run 지속시간도 60초→20초**로 바꾸므로 원재료 총량과 변환율의 2단계 감속이 생긴다.
- 최초 스킬 가격/선행조건을 또 무조건 ×6하거나 기존 구매 내역을 초기화하는 **삼중 너프 금지**. 일단 `baseCost`와 `costGrowth=1.6`을 그대로 두고 20초+0.06 변환 결과를 측정한다.
- 60초 자동 로그에서 첫 0~20초 원재료는 시드31415 약 **2,836 Raw**(0~10초 834, 10~20초 2,002). 고정 비율만 적용하면 약 **170 Photon + Refinery 보너스**가 된다. **이는 시뮬레이션 수치에 대한 산술 가설**이지 20초 신버전 실측이 아니다. 움직임/스폰/시간정책 변경 후 반드시 재측정한다.
- 첫 인간 Run에서 **의미 있는 스킬 1~3회 구매**, 5 Run 이후에도 적어도 한 개의 유효 구매 선택이 남는 것을 목표로 한다. 근거 없는 구매 제한을 강제하지 않는다.

### 5.3 Shard Refinery (Plinko-lite가 아닌 Shard Storm 표현)

게임 종료 후 RESULT 화면의 중앙에 **Shard Refinery**가 열린다. 단순한 2D 페그 보드/바운스 애니메이션은 가능하지만 별도 물리 라이브러리는 설치하지 않는다.

- 수집한 Raw를 **8~12개의 묶음(토큰)**으로 분리한다. 실제 도형 수만큼 수백 개를 떨어뜨리지 않는다.
- 5개 결과 슬롯, 초기 배율 및 가중치:

| 슬롯 | 배율 | 선택 가중치 |
|---:|---:|---:|
| 1 | ×0.80 | 15 |
| 2 | ×1.00 | 35 |
| 3 | ×1.10 | 30 |
| 4 | ×1.30 | 15 |
| 5 | ×1.60 | 5 |

- 슬롯 평균 배율 기댓값은 **약 ×1.075**. 한 판에 영구적으로 몇 배가 튀는 잭팟은 초기에는 허용하지 않는다.
- 각 묶음의 Raw 몫은 동일(나머지는 마지막 묶음)에 가깝게 배분한다. `payout = floor(sum(eachRaw * conversionRate * selectedSlotMultiplier))`.
- **정산 슬롯은 미리 Run 결과로 결정적으로 확정**한 뒤 토큰이 해당 슬롯까지 튀어 내려가는 애니메이션을 재생한다. 애니메이션과 실제 지급 결과가 달라선 안 된다.
- 보드 연출은 **최대 약 1.5초**, 기본 속도는 더 빠르게 조절할 수 있다. **Skip/즉시 정산 버튼**에서 같은 보상을 지급하며 게임 입력을 기다리지 않게 한다.
- `setTimeout`으로 잔액을 여러 번 더하지 않는다. `refinerySettlementId`/settled flag와 Run 기록의 payout을 사용해 **정확히 1회 은행 반영**한다.
- Refresh/Play Again/뒤로 가기/Skip/애니메이션 완료를 연속 실행해도 **재화는 한 번만 증가**한다. 메모리 내 결과와 localStorage 정산 시점에 안전한 상태 전이가 있어야 한다.
- `first click` 등의 연쇄 계산은 변하지 않는다. Refinery RNG는 게임플레이 스폰 RNG와 독립된 스트림 사용.
- `Refinery OFF` 개발자 토글은 바운스 연출을 생략하고 슬롯 보정 없는 ×1 고정 변환을 사용한다. 이 옵션은 **경제 결과가 달라지는 실험 토글**이며 real save와 A/B를 혼동하지 않는다.
- RNG를 조작해 Refresh로 높은 배율만 반복 추첨하는 리롤 악용 방지. 정산 결과는 한 번만 생성하고 기록한다.

### 5.4 20초 Run → Refinery → Skill의 UX

`START → PLAYING 20s → RUN END → REFINERY (0~1.5s, Skip) → RESULT / SKILL TREE → PLAY AGAIN`

- 새로운 결과 메뉴를 또 여러 페이지로 늘리지 않는다. **Refinery·정산 금액·Skill Tree를 같은 결과 화면**에서 순서대로 표시한다.
- 표기: `Raw Shards 2,836 → Processing ×1.08 → Photon +183`(숫자는 예시).
- v0.8과 동일하게 Game 종료에서만 스킬 구매 가능.
- 목표 UX: **전투 외 정산 대기 최대 1.5초**, Skip 시 즉시 구매 가능, 다음 Run 시작 1클릭.
- 20초 게임보다 보상 애니메이션/상점 클릭에 더 오래 머무르게 하지 않는다.

## 6. P0 시간 강화와 비용

- `duration = 20 + 2*extraTimeLevel`, 최대 Lv.6 = 32초.
- `Extra Time`의 소유 레벨은 보존, 소유자에게 현재 60~90초가 20~32초로 바뀌었음을 UI에서 명확히 설명.
- **v0.8 사용자의 이미 구매한 Extra Time Lv은 소거하지 않는다.** 가격을 기존에 지불했으므로 선택적 1회 respec 기능을 제공한다면 해당 노드에 쓴 누적 기존 비용만 정확히 환불한다. 범용 무료 스킬 초기화나 은행 초기화 금지.
- 개발자 비교는 **모든 빌드를 동일 20초로 고정한 DPS/원재료 실험**, 실제 증가 시간으로 플레이하는 **실제수익 실험**을 분리한다. 20→22초 수익이 과도하면 비용 조정 후 증거를 남긴다.

## 7. P1 장기 콘텐츠: 자원 등급·신규 도형·신규 스킬 계층

**P0이 재미를 유지하면서 작동한 후 구현한다.** 새 스킬만 수십 개 채워 넣는 방식보다, 획득할 수 있는 자원과 파괴 방식 자체가 단계적으로 늘어나도록 한다.

### 7.1 Lifetime Discovery Rank (Run UI와 별개)

- `lifetimeDestroyed`: **실제 정산 완료된 Run의 누적 완전 파괴 수**. `highestTier`는 종전처럼 해당 Run 내부 수치.
- `discoveryRank`: 정산 완료 Run의 lifetimeDestroyed에 따른 영구 해금 등급. 별도 Sector 선택/우주지도 화면 불필요.
- **기존 save에서 마지막20 Run만 기록되어 있으면 전체 lifetimeDestroyed를 정확히 복원할 수 없다.** 과거 기록 합계는 `knownHistoryKills`로 별도 보존하며, 정확한 누적 카운터를 거짓 생성하지 않는다. 새 v0.9부터의 진짜 누적치와 마이그레이션 추정치를 표시/분리한다.
- 기존 올맥스 계정은 새로운 발견/촉매를 통해 추가 콘텐츠가 활성화되며, 초기 은행이 크다고 새로운 장기 재료를 즉시 전부 구매할 수 없게 한다.
- 새 해금은 실제 플레이 20초 Run의 **정산 과정에서 확정**한다. 스킬 가용 여부/등장 종류가 같은 Run 중간에 계정 기록 때문에 소급 변경되지 않는다.

| Discovery Rank | 누적 정산 파괴 목표 (초기) | 새로운 목표 |
|---|---:|---|
| 0 | 0 | 기본 4종·기본 Refinery·11기존 노드 |
| 1 | 300 | `Prism Ore` 등급, Refinery 첫 확장 슬롯/노드 |
| 2 | 1,200 | `Core Ore`, 보호막형 Hex 도형, 고급 Shard 분기 |
| 3 | 3,500 | `Reactor Node` 유형, 특수 계승/폭발 분기, 희귀 촉매 |
| 4 | 8,000 | 거대 도형 `Ancient Core`, 새로운 장기 목표·Relic 후보 |

이 숫자는 v0.8 **자동 입력 성능을 고려한 튜닝 출발점**으로, 사람 한 판당 파괴 수 분포를 확보한 뒤 조정한다. **총 3~5회만에 Rank4 도달하면 실패**로 기록한다.

### 7.2 광석 등급은 형태/Modifier와 분리한다

광석 등급 `oreGrade`는 `triangle/square/pentagon/star` 또는 `cracked/charged/enhanced`와 별개이다. **초기에는 외형 장식(도형 안 작은 상징), 희귀 드롭 정산 효과**만 추가한다.

| 등급 | 해금 | 생성 시 확률 가설 | 파괴 시 추가 Raw | 촉매 |
|---|---|---:|---:|---|
| Common | Rank0 | 나머지 확률 | 0 | 없음 |
| Prism | Rank1 | 8% | +15 | 없음 |
| Core | Rank2 | 2% | +60 | 소형 Catalyst 1개(정산 후) |
| Void | Rank4 | 0.5% | +180 | Catalyst 2개 |

- 등급 확률은 **해금된 종류만** 적용하고 남은 확률은 Common. 종류/색/고유 공격 특성을 바꾸지 않는다.
- 높은 등급도 직접 클릭/연쇄 파괴 양쪽에서 드롭. 자동 수집; 수동 주워담기 없음.
- Raw 추가분은 `actualDamage + destroyBonus` 외 **별도 명시적 드롭**으로 한 번 지급. 직접 피해 중복 지급 금지.
- 더 높은 rarity로 Photon이 기하급수적으로 폭증하지 않도록 **전체 Raw 수익에서 희귀 등급의 기여율**을 로그로 추적한다.
- Core/Void의 Catalyst는 단순 재화 부스팅이 아닌 **새 노드의 희소 해금 재료**로 사용한다. 실제 획득한 촉매만 저장.
- 희귀 등급 텍스트/문양으로 구분, 원래 4종의 외곽선 색은 유지.

### 7.3 신규 파괴 콘텐츠 (새로운 게임 방식만)

| 콘텐츠 | 해금 가설 | 피격/파괴 특성 | 선택의 이유 |
|---|---|---|---|
| **Hex Shield** | Rank2 | 기본 HP 8, 첫 강한 타격에 장갑 링 균열, 완전 파괴 시 **근처 약한 도형에 짧은 보호막 해제 파동** | 직접 클릭으로 방어를 벗길 이유 |
| **Reactor Node** | Rank3 | HP 12, 내구도 50% 이하 도달 시 파동 1회, 완전 파괴 시 별도 1회 | 부분 파손에도 독립 이벤트 |
| **Ancient Core** | Rank4 | HP 30, 75/50/25% 장갑 단계마다 파편·충격파, 파괴 시 특별 Raw·촉매 | 직접 파괴+연쇄의 협동 고가치 목표 |

- 기본 4종의 역할과 차별화되지 않는 변종은 추가하지 않는다. 각각의 고유 효과는 동시 난사 대신 **시간차 인과관계**를 가진다.
- 이미 20초 진행 중 뒤늦게 보스 등장/종료 조건을 강제하지 않는다. Ancient Core도 단순 고가치 드문 대상이고 시간0에서 정상 종료.
- 새 도형은 계정 Discovery Rank와 해당 Run 누적 파괴 Tier를 **둘 다** 만족할 때 보충 목록에 추가. 아직 살아 있는 도형은 유지.
- 내부 `shapes` 타입을 늘릴 때 기존 튜토리얼/가중치/테스트를 깨지 않도록 선언적 타입 등록을 적용한다.
- 위 도형들은 P1 전부를 즉시 구현하는 명령이 아니라 **계층별로 플레이 테스트 후 추가할 범위**다.

### 7.4 새 스킬 가지 설계 (11개 기존 유지, 신규만 늦게 노출)

| Branch | 노드 예시 | Rank 조건 | 효과 예시 / 제약 |
|---|---|---|---|
| Destroy | `Precision Fracture` | 1 | Cracked 직접 파괴 시 Raw +소량(중복 1회 방지) |
| Cascade | `Fragment Relay` | 2 | 파편 사망 효과 뒤 1개의 약한 보조 파편 생성, 피해 계승 안 함 |
| Cascade | `Kinetic Reach` | 2 | 회전하는 도형에 적중한 주 파편 비행거리 소폭 증가, 대상 추적 아님 |
| Reaction | `Resonance Layer` | 3 | Reactor/사각형 충격파 연결 반경 소폭 증가 |
| Refinery | `Yield Stabilizer` | 1 | 낮은 슬롯 보정 향상, 전체 ×2 잭팟 금지 |
| Refinery | `Rare Separator` | 2 | Core 광석의 추가 Raw 수익 +고정값 |
| Utility | `Salvage Scanner` | 3 | 다음 Run의 희귀 등급 확률 소폭 증가 |
| Legacy | `Catalyst Channel` | 4 | Core 촉매 조건을 만족할 때만 고급 특성 해금 |

- 모든 노드에 **ID / 위치 / 선행조건 / 최대 레벨 / 정확한 효과 / 최초 비용 / 소비 촉매 / 보이는 미리보기**가 있어야 하며, 노드와 부모 관계의 무효 참조/순환 검사 필수.
- 기존 11개는 저장 호환을 보장한다. 신규 노드는 개별 id에서 레벨0으로 추가.
- **모든 가지의 조건이 하나로 합쳐지는 사실상 선형 경로 금지.** 두 경로에서 선택 가능한 기회비용이 남도록 한다.
- 정식 구현 우선순위는 **Refinery 2개 + Cascade 2개 + Destroy 1개**로 시작하고, 플레이 결과를 본 다음 확대한다.
- `Catalyst Fragments` 소비는 고급 능력 해금에만 제한하며 파괴 확률을 돈으로 뽑는 시스템은 아니다.

### 7.5 후속 보류 기능

- 획득형 `Anomaly Cache`: 특별 도형/기록으로 얻는 키로 무료 개봉, **지급 확률 공개**, 외부 결제/현금/재화 판매 불필요. 초기 프로토타입 P0/P1에는 넣지 않는다.
- Artifact/Relic: 고유 보스/업적 보너스, 낮은 빈도로 영구 해금. P2 후보.
- Prestige: 신규 콘텐츠가 소비된 후에도 반복 플레이 재미가 있는지 확인하고 도입. 강제 리셋 금지.
- 제작비가 큰 3D 파편·복잡한 물리 강체·유료 가챠·다중 우주선/사격 모드·온라인 랭킹은 범위 밖.

### 8.3 성공 가설과 튜닝 순서

**가설 (사람 5~10 Run으로 판단, 확정 수치 아님)**

1. 첫 클릭/첫 연쇄의 쾌감 v0.8 이상 유지, 20초가 끝날 때 '조금 더 부수고 싶다'가 발생.
2. 새 계정 최초 Run 이후 스킬 **1~3개** 구매, 5 Run 후에도 유효 노드·희귀 자원·다음 Discovery 목표가 남음.
3. 기존 계정 올맥스도 새 콘텐츠에 접근할 **명확한 장기 목표**가 존재.
4. 코스메틱/모션 때문에 억울하게 빗나간 클릭이 드물어야 하며 파편 인과관계가 이해 가능.
5. Refinery가 가치를 느끼게 하되 정산 시간을 낭비시키지 않음.
6. 안전 cap·지연 이벤트·중복 보상/파괴 판정 오류 없어야 함.

튜닝 순서:
1. 클릭/충돌 정확성, 가시성 복구.
2. 20초 내 도형 해금 리듬·희귀 도형 빈도 조정.
3. `conversionRate` 또는 Refinery 슬롯 분포 조절.
4. 기존 스킬 가격·효과를 **그 다음** 조정(한 번에 변수를 여러 개 바꾸지 않음).
5. Discovery Rank·촉매 드롭/신규 노드 분기 간격을 실측으로 조정.

지속시간 20초라는 이유만으로 자동으로 모든 노드를 강제 잠금하거나 대량 가격 인플레이션을 적용하지 않는다.

## 13. 성공 판단 기준

최소 5회 사람 플레이 후 다음을 물어본다.

- 이전 v0.8과 비교해 **20초짜리 한 판이 더 집중되고 다시 누르고 싶은가?**
- 모션이 보기 좋으면서 **클릭 실패나 연쇄 충돌을 오히려 방해하지 않는가?**
- `Refinery` 보상 정산을 기대하게 되는가, 아니면 Skip만 누르게 되는가?
- **다음 해금할 원석/노드/특수 도형**이 명확해서 한 판 더 하고 싶은가?
- 5회차에 이미 모든 주요 스킬이 소진되지 않았는가?
- 플레이어가 최적의 클릭 대상이나 Skill 경로를 **스스로 선택할 여지**가 있는가?

**핵심 성공 조건:** 파괴감은 유지하면서, 20초 Run의 반복 플레이를 더 경쾌하게 하고 새 보상 단계/발견 목표가 성장의 속도와 수명을 개선한다.
