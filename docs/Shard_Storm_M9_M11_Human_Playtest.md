# M9.0~M11 — 실제 사람 플레이 검증

자동 입력·통제 fixture로 기능과 정산을 검증해도 재미나 재도전 의향은 확정할 수 없습니다. 아래 항목은 사람 플레이로 확인할 미검증 영역입니다. 개발 승인 대기 단계는 아닙니다.

## 진행 방법

기존 실제 세이브는 먼저 내보내 보관합니다. 비교용 지급·도형 강제 생성은 Fresh Lab에서만 사용합니다. 자연 성장 계정의 결과와 강화 fixture 결과를 나눠 기록합니다. 기본 Normal/20초를 먼저 플레이하고, Extra Time이나 Anomaly를 추가할 때 조건을 기록합니다.

1. 처음5 Run: 안내 없이 시작·홀드·드래그·정산·스킬 구매가 이해되는지 관찰합니다. 빈 화면 시간, 놓친 클릭, 읽기 어려운 표시, 다음 Run을 누른 이유를 기록합니다.
2. 동일 성장 단계에서 Crusher/Cascade/Reactor를 각각3 Run: Signature3/Evolution2의 슬롯 제한이 선택을 만드는지 확인합니다. 구매와 활성화의 차이, 미소유·비활성·슬롯 가득 참이 읽히는지 확인합니다. 총 파괴량만으로 선호 빌드를 결정하지 않습니다.
3. 특수 타깃: Hex 방어 해제→Conductor, Fuse→Reactor, Mirror/Gravity 경로 변경, Repair를 남겼다가 제거하는 선택을 실제로 시도합니다. 동시에 너무 많은 연결선·파편이 보이는지 관찰합니다.
4. M11: Portal을 통해 먼 타깃을 맞히기, Phase 취약 창 기다리기, Beacon을 Chain10 뒤에 제거하기, Shifter 예고 뒤 새 좌표 조준, Lens 굴절로 두 타깃 맞히기를 시도합니다. 성공/실패를 화면과 Codex 설명으로 이해할 수 있는지 확인합니다.
5. Codex: 최대2개를 pin하고 한 기술을 의도적으로 노립니다. 정산 전 pending과 정산 후 확정의 차이, 단계 II 이전의 기술 저장, badge/별칭 보상을 이해하는지 확인합니다. 막힌 과제를 기술 설명·도형 출현 부족·조준 난도·빌드 충돌 중 무엇으로 느끼는지 기록합니다.
6. Elite: 요구 Rank/insight에 도달한 비교 계정에서 기존 Arena에 섞여 등장하는 타깃의 우선순위를 판단합니다. 별도 보스 화면 없이도 핵심 타깃과 보상을 알아보는지 확인합니다. 강제 해금한 계정의 결과로 자연 해금 속도를 추정하지 않습니다.
7. 접근성: 일반/Focus,620px 좁은 창, Reduced Motion/Shake OFF에서 타깃 가림·UI 접근·조준 위치를 확인합니다. 기록20개가 쌓인 계정에서 결과·구매·다음 Run 시작의 저장 지연이 거슬리는지도 확인합니다.

## 기록할 항목

|항목|기록|
|---|---|
|조건|자연/fixture, seed, Rank,20/Extra Time, Normal/Anomaly, 활성 Signature/Evolution/Relic|
|선택|먼저 공격한 타깃과 이유, 기다린 순간, 실패한 조준|
|이해|알아본 도형·효과, 설명이 부족한 기술, 잘못 예상한 상호작용|
|피드백|클릭 만족감1~5, 타깃 가림, 흔들림 불편, 빈 화면|
|성장|구매한 효과를 느꼈는지, 다음 구매·기술 목표, 막힘 이유|
|재도전|다음 Run을 누른 이유 또는 그만둔 이유, 바꾸고 싶은 빌드|

50/100/200/300 자동 Run의 잔고·해금 결과는 비교 기준으로만 사용합니다. 사람이 동일한 속도로 성장하거나,19개 Codex를 완성할 때까지 계속 플레이한다고 해석하지 않습니다. 기존 가격 일괄 인상·재화 초기화 없이 먼저 실제 정체 구간과 선택 빈도를 관찰합니다.

## 후속 후보

기술 설명과 원인 피드백의 부족, 과도한 연결선, 특정 Codex의 의도적 공략 난도, 후반 잉여 재화와 목표 소진을 먼저 검토합니다. 고비용 Shader·전용 생성 연출·진짜 물리 슬로모션은 [Deferred VFX TODO](Shard_Storm_Deferred_VFX_TODO.md) 범위로 유지합니다. 기존512 tick iteration 안전 상한의 도달 빈도와 실제 체감도 함께 확인합니다.
