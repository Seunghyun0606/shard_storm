# Shard Storm — Codex 개발 전달용 프로토타입 기획서 v0.7

> 상태: 플레이 테스트용 구현 명세 (정식 게임 기획 아님)
> 타깃: PC 웹 / 마우스 / 로컬 실행
> 기술: HTML5 Canvas 2D + Vanilla JavaScript(ES Modules) + HTML/CSS + localStorage
> 목표: **즉각적인 클릭 타격 → 시간차를 두고 전파되는 물리 연쇄 → 시각적으로 다양한 도형 군집 → 60초 종료 → 분기형 영구 스킬 트리 → 재도전**의 재미를 최소 비용으로 검증한다.
> 업데이트: v0.6을 대체하는 **전체 구현 기준 문서**. v0.7 추가 범위는 시간차 연쇄, 직접 클릭 VFX, 모양·재질·배치 다양화, 연결선이 있는 확장형 스킬 트리 UI.
> 중요: 이미 구현한 v0.6 프로젝트가 있으면 재작성하지 말고 기존 코드를 수정·확장할 것. 기존 저장 데이터도 마이그레이션해 보존할 것.

## 0. Codex 작업 지시

이 문서를 단일 구현 기준(source of truth)으로 사용해 **로컬에서 실제 플레이 가능한 완결된 프로토타입**을 만들어라. 디자인 시안, 의사코드, 정적 화면만 제출하지 말 것. 빠르게 구현하되 아래 수치와 판정 규칙은 임의로 바꾸지 말 것. 중요한 모순 또는 기술적 불가 사항이 있다면 합리적인 최소 변경으로 해결하고 README에 변경 사항을 기록하라. 이미 이전 버전이 있다면 파일/구조/세이브를 최대한 재사용하고, 기능을 통째로 갈아엎지 말 것. 기능을 지나치게 일반화하거나 엔진, 패키지, 백엔드, 외부 이미지를 추가하지 말 것.

**완료 산출물:** 실행 소스 전체, README(실행·조작·구조·알려진 문제), 테스트 코드/결과, 개발자 패널, 60초짜리 반복 가능한 게임, 영구 저장. 브라우저 실행 검증과 스크린샷 수집이 가능한 환경이면 수행하고 경로를 알려라. 불가능하면 사실대로 명시하라.

## 1. 확정된 게임 원칙

1. 게임 한 판(Run)의 **기본 시간은 정확히 60초**, 시작부터 종료까지 **단일 타이머**를 쓴다. 중간 단계별 타이머 초기화는 없다.
2. 화면 전환 없이 **한 아레나에서 계속 직접 파괴**한다. 레이저, 발사기, 탄약, 이동 캐릭터 없음.
3. 누적 **완전 파괴 수 12 / 30 / 55 / 90 / 140**을 넘을 때마다 다음 도형·변종·밀도가 **기존 도형과 섞여 순차적으로** 등장한다. Sector 또는 Round 이동 화면은 없다.
4. 한 단계의 도형을 전부 비워야 해금되는 방식이 아니다. 도형은 제한시간 동안 계속 보충된다.
5. **시간이 0이 되면 무조건 Run 종료.** 미파괴 도형을 따로 계산해 실패시키지 않는다. 성과는 파괴 수, 연쇄, 획득 재화로 비교한다.
6. 획득 광자는 해당 Run 종료 때 은행에 한 번만 정산된다. 이후 **영구 스킬 트리**에서 구매하고 새 Run은 첫 단계부터 시작한다.
7. **Extra Time** 영구 강화로 다음 Run의 총 제한시간을 레벨당 5초씩, 최대 90초까지 늘릴 수 있다.
8. **파편은 자동 추적하지 않는다.** 도형 파괴 지점에서 발생하고 지정된 방향으로 직선 이동/충돌/벽 반사한다. 짧은 수명 후 사라진다.
9. 도형은 부분 손상 시 모서리가 깨진 것처럼 보이되, **실제 다각형 절단 물리 엔진은 구현하지 않는다**.
10. 모든 주요 수치와 옵션은 `config.js`에서 바꿀 수 있어야 한다.
11. **순차적 전파가 본 게임의 핵심 시각 규칙**이다. 파편은 실제 이동거리 이후 충돌하고, 충격파는 퍼지는 원이 대상에 도달했을 때 피해를 준다. 한꺼번에 피해를 계산하고 폭발 애니메이션만 늦추는 방식은 금지한다.
12. 클릭은 명중 시 즉시 반응(충격 링·플래시·균열·작은 파손 조각)이 보여야 한다. 클릭 장식 링은 기본적으로 피해가 없다.
13. 동일 종류의 도형이라도 **윤곽·회전·가로세로 비율·채도·명도·안쪽 무늬**가 달라 보이도록 프로시저럴 변종을 생성한다. 색만으로 도형의 게임플레이 종류를 구분하도록 만들지 않는다.
14. 스킬 구매 화면은 **연결선과 선행조건이 보이는 노드 그래프** 형태로 표현하고, 선언적인 데이터 정의로 노드를 추가할 수 있게 만든다. 일반 스킬 5개의 가격·성장 효과는 이전 버전과 동일하게 유지한다.

### 이번에 만들지 않을 것

보스, 진짜 강체 물리·도형 간 충돌 피해, 랜덤 로그라이크 카드, 프레스티지, 로그인/서버, Steam 연동, 모바일 최적화, 온라인 랭킹, 고급 에셋, 복잡한 상점·퀘스트, 음원 파일, Sector 선택 화면.

## 2. 게임 화면 / 입력

- 논리 해상도 `960 × 540`. 브라우저에서는 비율을 유지해 크기 조절하고, 클릭 좌표를 논리 좌표로 변환.
- 게임 아레나: `x=32..928`, `y=78..512`. 상단 HUD와 구분. 도형이 가장자리에 겹쳐 나오지 않게 반지름을 고려한다.
- 상단 HUD: `남은 시간(소수 첫째 자리)`, `누적 완전 파괴 수`, `Run 중 얻은 광자`, `현재 연쇄/최대 연쇄`.
- 일반 화면에 Stage/Sector 숫자는 표시하지 않는다. 해금 시 새 도형의 0.15초 등장 효과만 보여준다.
- 좌클릭: 커서 아래 도형 1개에 즉시 공격. 누르고 있으면 `0.20초` 간격으로 반복 공격. 드래그 중 타깃 변경 가능.
- 초기 직접 공격력 `3`. 무제한 공격이지만 한 공격 주기에는 1개 도형만 타격한다. 빈 공간 클릭 시 타격 없음.
- 대상으로 삼을 도형은 커서 중심에서 가장 가까운 도형 1개. 도형의 실제 외형과 가깝고 클릭하기 쉬운 **원형 히트 반경** 사용. UI 위 클릭은 공격하지 않는다.
- 마우스가 창 밖으로 나가거나 버튼을 놓으면 홀드 공격 중지.
- **성공적인 클릭 타격 VFX (필수):** 클릭 위치에 0.12초 동안 반경 8→26px로 커지며 사라지는 얇은 충격 링, 0.055초 흰색 타격 플래시, 0.10초 동안 도형 크기 1.08→1.0 반동, 2~4개의 손상 조각(0.15초)을 표시한다. 내구도가 남으면 금/모서리 손상을, 파괴되면 더 큰 고유 효과를 이어서 보여준다.
- **빈 공간 클릭:** 희미한 0.07초 작은 커서 파동만 재생하고 피해·재화는 발생하지 않는다. 홀드 중 링 과다 중첩을 피하기 위해 클릭 반응 VFX를 풀링하고 최대 수를 제한한다.
- **클릭 링은 장식 전용**이며 실제 범위 피해는 없다. 후속 스킬 `impactPulse`를 구매한 경우에만 성공적인 직접 타격을 주변 피해로 확장한다.
- 파티클/화면 흔들림은 시각 효과이며 실제 판정·타이머에 영향을 주지 않는다.
- 브라우저 탭이 비활성화되면 일시정지. 복귀 시 시간 점프 없이 이어서 진행. 게임 중 수동 일시정지 버튼은 MVP에서 선택 사항.
- 화면 상태: `TITLE → PLAYING → RESULT+UPGRADES → PLAYING`. `TITLE`에는 Start 버튼 하나로 충분하다.

## 3. 도형 기초 수치

| 종류 | 기본 HP | 완전 파괴 광자 보상 | 완전 파괴 효과 | 기본 역할 |
|---|---:|---:|---|---|
| Triangle | 3 | 5 | 파편 3개, 각 피해 3 | 연쇄 시작 |
| Square | 4 | 8 | 반경 90px 충격파, 피해 2 | 광역 약화 |
| Pentagon | 5 | 12 | 주 파편 2개(피해 3), 충돌 시 각 2개로 분열(소형 피해 1) | 분기 확산 |
| Star | 9 | 40 | 반경 145px 폭발, 피해 5 | 잭팟·광역 파괴 |
| Enhanced | 원본 HP + 2 | 원본 보상 ×1.5 (올림) | 원본 고유 효과 유지 | 후반 난도 |

- **형태 = 게임플레이 종류, 윤곽선 색 = 효과 종류**를 일관되게 유지: Triangle 청록 `#6ADFEF`, Square 분홍 `#F4A6D2`, Pentagon 보라 `#C7ADFF`, Star 금색 `#FFD884`. 외곽선은 종류별로 고정하되 내부 채색은 같은 종류에서도 3~4개 재질/팔레트로 변화시킨다.
- **모양 변종은 동일한 종류를 유지:** Triangle은 좁은/넓은/비스듬한 3꼭짓점, Square는 직사각형/비스듬한 사변형, Pentagon은 넓은/길쭉한/불균형한 5각형, Star는 뾰족/통통한 5각 별. 아래 §6.1 상세값 참조.
- 표면은 채도·명도·내부 무늬(중심선, 마름모 코어, 내부 테두리)를 다르게 하되 **표면 변종은 HP·공격 효과가 동일한 코스메틱**으로 시작한다. 메커니즘이 다른 강화 변종(`Enhanced`)만 HP+2와 이중 외곽선/작은 장갑 표시를 함께 쓴다.
- 부분 손상은 **남은 HP 비율에 따라 균열과 모서리 깎임을 3단계로 표시**한다. 공격마다 실제 폴리곤 메시 절단은 금지.
- 피해는 정수. HP가 0에 도달하면 `destroyed` 표시를 먼저 하고 파괴 보상 및 고유 효과를 **정확히 한 번** 처리한다.
- 모서리 파편 VFX와 공격 파편은 다르다. 부분 손상으로 튀는 시각 조각은 피해가 없고 0.2초 내 소멸한다.
- 도형은 기본적으로 고정되어 있고, 충격파를 받으면 **최대 18px의 짧은 이동 연출**만 수행한다. 그 움직임 자체는 충돌 피해를 발생시키지 않는다.

## 4. 공격 파편 / 충격파 명세

### 4.1 공통 공격 파편

- 기본 속도 `700 px/s`, 기본 최대 비행거리 `180px`. **파편 최대 수명은 `min(0.50초, 현재 최대 비행거리 / 700 + 0.02초)`로 동적 계산**한다. 기본 약 0.28초이며, `Shard Range` 강화 후 늘어난 거리도 끝까지 이동할 수 있어야 한다.
- 주 파편 및 Triangle 파편은 기본 벽 반사 **1회**, 반사 후에도 남은 총 거리와 수명만큼만 이동.
- 파편은 목표를 추적하거나 방향을 보정하지 않는다. 파편끼리 충돌하지 않는다.
- 도형과 처음 충돌하면 타격한 뒤 소멸한다. 관통 기능은 MVP에서 구현하지 않는다(‘Piercing Shards’라는 과거 명칭을 이유로 관통시키지 말 것).
- 빠른 이동에서 충돌을 누락하지 않도록 **이전 좌표→다음 좌표 선분 대 원형 히트영역**으로 검사한다. 가장 먼저 충돌한 대상에만 피해 적용.
- 생성한 도형은 이미 파괴되므로 재타격 불가능. 공격 효과의 소유/최초 Chain ID를 기록한다.
- 고유 공격 파편은 사망 후 **0.03초 지연 발사**한다. 대상을 추적하거나 매 프레임 궤도를 꺾지 않는다.

### 4.2 Triangle

- 파괴 지점 중심에서 파편 **3개**가 원래 도형의 세 꼭짓점 방향(120도 간격)으로 나간다.
- 도형은 생성 시 회전 각도가 지정되고 화면 표시 방향과 실제 파편 진행 방향이 일치한다.
- 기본 피해는 각 3. `Shard Power` 레벨당 +1.

### 4.3 Square — 시간차 충격파

- 파괴 시 중심에서 반경 `90px`까지 확대되는 **실제 공격 충격파**를 생성한다. 피해 `2`, 확산 속도 `650px/s`(90px를 약 0.138초에 통과). `Chain Amplifier`의 반경/피해 증가를 반영한다.
- 생성 시점에 반경 내 모든 대상 HP를 즉시 깎지 않는다. 각 물체 중심과 폭발 중심의 거리를 계산하여 파동의 외곽이 해당 거리까지 확장했을 때만 피해 이벤트를 발생시킨다. 물체의 히트 반경을 고려하되 한 파동에서 한 대상은 딱 한 번.
- 더 가까운 물체가 먼저 파괴되고 그 물체의 고유 효과가 새 연쇄를 발생시킨다. 같은 거리의 대상은 같은 틱에 맞을 수 있으며, VFX에만 최대 20ms 소규모 시차를 둘 수 있다(판정과 표시의 의미가 크게 어긋나지 않도록).
- 사각형 충격파의 외형은 핑크 링 + 원 테두리상 작은 균열. 피격된 도형은 짧은 넉백 연출(최대 18px)만 한다. 넉백 이동 자체에 추가 충돌 피해 없음.
- **링이 먼저 닿았는데 도형이 나중에 깨지는 연출을 하거나, 링 도달 전 미리 파괴하는 연출을 금지한다.**

### 4.4 Pentagon

- 파괴 중심에서 `도형 회전 기준 방향 ±45도`로 주 파편 2개 발사(피해 3).
- 주 파편이 **다른 도형에 처음 충돌하면**, 그 자리에서 충돌 당시 진행 방향 ±35도로 작은 파편 2개 생성. 주 파편은 충돌 피해 처리 후 소멸.
- 작은 파편: 피해 1, 거리 90px, 속도 700px/s, 수명 최대 0.15초, 벽 반사 없음, 재분열 없음. 방금 맞힌 도형은 즉시 재타격하지 않도록 제외하거나 생성 위치를 충돌점 밖으로 오프셋.
- 주 파편만 `Shard Power` 및 `Shard Range` 증가 적용. 소형 파편은 MVP에서 고정 수치.

### 4.5 Star — 시간차 광역 폭발

- 파괴 시 중심에서 반경 `145px`까지 확대되는 금색 **실제 공격 폭발파**, 피해 `5`, 확산 속도 `720px/s`(약 0.201초에 외곽 도달).
- 충격파와 동일하게 파동이 도형에 도달한 시점에 피해. 범위 전체 즉시 피해는 금지한다.
- `Chain Amplifier` 레벨마다 피해 +1, 반경 +15px. 반경이 커져도 확산 속도는 일정해서 멀리 있는 도형은 더 늦게 깨진다.
- 금색 다중 링 + 6~12개 장식 파편. 별형 주변에 있는 도형이 중앙에서 바깥쪽으로 **순차적으로 부서지는 잭팟 장면**이 보여야 한다.
- 별도 숨은 재화 배율 없음(기본 보상 40). 실제 파괴한 대상의 보상만 정상 지급.

### 4.6 피해/연쇄 판정 순서 — 스케줄링 규칙

1. 마우스 성공 타격은 **즉시** 피해 이벤트를 처리하고 클릭 링/균열/플래시를 표시한다. `chainId` 신규 부여.
2. 파편 명중은 실제 이동 후 충돌 타이밍에, 충격파는 외곽이 대상에 도달한 타이밍에만 `DamageEvent`를 추가한다. 모든 월드 이벤트는 `simulationTime`과 `chainId`, `sourceKind`, `generation`을 가진다.
3. `DamageEvent`가 실행될 때 살아 있는 대상에게 실제 피해 `min(공격 피해, 현재 HP)` 적용 및 해당 수량 Photon 지급.
4. HP가 0이면 즉시 `destroyed` 플래그를 먼저 설정한 후, 완전 파괴 보너스와 Run 카운트를 정확히 한 번 적용.
5. 해당 도형의 고유 후속 효과를 **현재 시뮬레이션 시간 + 0.03초**에 발사·확산 시작하도록 이벤트 큐에 예약한다. 계승 효과도 같은 방식으로 예약하되 보조 효과는 재계승 금지.
6. 후속 파편의 실제 충돌이나 파동 전달이 다음 도형을 파괴하면 위 과정을 반복한다. 이것이 "화면에서 순서대로 번져 나가는 연쇄"다.
7. 동시 도착 이벤트는 `scheduledTime → priority → monotonicEventId` 순으로 안정 정렬하고 처리해 Seed 재현성을 유지한다. 동일 도형 파괴 이벤트 중복 금지.
8. Run 종료 시점(`timeRemaining = 0`) 이후 예정된 이벤트는 피해·재화 없이 무효화하고, 남은 효과는 시각 잔상으로만 소멸한다.

#### 전파 리듬 (튜닝 초기값)

| 이벤트 | 기준 시점 | 목표 시간 | 비고 |
|---|---|---:|---|
| 클릭 타격 피드백 | 클릭 | 0~0.12초 | 피해는 즉시 |
| 도형 균열/부서짐 | 피해 시각 | 0~0.15초 | 사망은 피해 적용 즉시 확정 |
| 사망 후 고유 효과 발사 | 사망 | +0.03초 | 파편·충격파 모두 |
| 파편 100px 이동 | 발사 | 약 0.143초 | 속도 700px/s |
| 사각형 충격파 최대 반경 | 발사 | 약 0.138초 | 속도 650px/s |
| 별형 폭발 최대 반경 | 발사 | 약 0.201초 | 속도 720px/s |
| 주요 다단계 연쇄 연출 | 최초 클릭 | 약 0.3~1.2초 | 사거리/밀도에 따라 달라짐, 강제 대기 시간 없음 |

**주의:** '연쇄를 순차적으로 보이게 한다'는 이유로 화면 전체의 피해 판정을 한꺼번에 하고 폭발 스프라이트만 차례로 재생하지 말 것. 시뮬레이션 자체에서 파편 이동/파동 확산 시점을 보장하되, 첫 클릭 반응만 즉시 처리한다.

### 4.7 파동 처리 구현 힌트

- 파동 객체: `{id, x, y, radius, speed, maxRadius, damage, age, chainId, sourceKind, generation, hitIds:Set}`. `radius = min(maxRadius, age*speed)`.
- fixed update에서 각 파동이 **직전 반경→새 반경** 사이에 통과한 도형을 검사해 피해 이벤트를 예약/실행한다(작은 히트 반경을 포함한 일관된 규칙 적용).
- 한 파동에 맞은 대상 ID는 Set으로 중복 방지. 파동은 최대 반경에 도착하면 시각 잔상 짧게 유지 후 제거한다.
- 가까운 대상부터 피해가 처리되어야 하므로, 같은 틱에 여러 대상과 접촉하면 `접촉거리/확산속도` 기준으로 정렬한다.
- 파편의 위치 갱신/충돌은 기존 4.1 규칙에 따라 처리한다. 직접 피해, 파편 피해, 파동 피해의 최종 처리는 하나의 `applyDamage`에서 통합한다.
- VFX(빛/흔들림)는 피해 판정과 분리하지만 **전파 지연은 판정과 VFX 양쪽에 동일하게 적용**한다.

## 5. 제한된 효과 계승 (A/B 비교 대상)

실험 기능으로 초기 ON, 개발자 패널에서 ON/OFF 가능. **아래 두 조합만 구현**한다.

| 마지막 치명타의 발생 원인 | 사망 대상 | 기본 효과 외 추가 효과 |
|---|---|---|
| Triangle의 **고유 파편** | Square | Square 중심에서 작은 바늘 파편 1개, 피해 1, 진행 방향은 명중 파편의 진행 방향 |
| Square의 **고유 충격파** | Triangle | Triangle 중심에서 작은 충격파 1개, 반경 45px, 피해 1, 확산 속도 650px/s |

- 직접 클릭으로 파괴한 도형에는 계승 추가 효과 없음.
- **고유 효과만** 계승을 유발한다. 계승으로 발생한 보조 파편/충격파는 다른 도형을 죽일 수 있으나 후속 계승을 전파하지 않는다.
- 여러 타격을 받은 도형은 HP를 0으로 만든 **마지막 타격의 효과 출처**를 사용한다.
- 고유 효과/계승 효과 각각 1회 생성. 보조 효과에서 자식 고유 효과는 정상 발생한다.
- 계승 ON/OFF에 따라 같은 난수 시드에서 결과를 비교할 수 있게 한다.

## 6. 도형 생성 / 해금 / 밀도

누적 수치는 한 Run 동안의 **완전 파괴된 도형 개수**이고, 해금 후 카운터를 초기화하지 않는다.

| 파괴 누적 | 등장 가능 종류 | 목표 동시 도형 수 | Triangle | Square | Pentagon | Star | Enhanced 확률 |
|---|---|---:|---:|---:|---:|---:|---:|
| 0–11 | T, S | 12 | 65% | 35% | 0% | 0% | 0% |
| 12–29 | +P | 16 | 45% | 35% | 20% | 0% | 0% |
| 30–54 | +Star | 20 | 40% | 30% | 20% | 10% | 0% |
| 55–89 | 강화 변종 | 24 | 35% | 30% | 20% | 15% | 20% |
| 90–139 | 밀도 증가 | 28 | 35% | 30% | 20% | 15% | 20% |
| 140+ | 강화 비중 증가 | 32 | 35% | 30% | 20% | 15% | 30% |

- 시작 시 12개 배치. 최초 배치의 일부는 **의도적으로 연쇄가 발생하도록** 고정하고 나머지는 seeded RNG 사용. 예: 중심 Triangle `(480,335)`, 같은 Triangle의 세 파편 방향에 반경 100~115px의 Triangle 3개 배치(발사 회전 각도를 동일하게 설정). 시작 안내로 중심 도형을 짧게 강조; 플레이어가 이를 눌렀을 때 최소 4개 연쇄를 보장. **나머지 8개 시작 도형은 이 세 파편의 초기 경로를 가로막지 않도록 배치**한다. 이후 배치는 무작위.
- 도형이 사망하면 부족한 도형 수를 계산하고, **0.2초 간격으로 한 번에 최대 3개**를 생성해 현재 목표 동시 수를 채운다.
- 생성 위치는 `x=32..928`, `y=78..512` 안. 다른 도형 중심과 최소 `양쪽 반지름 합 + 12px` 간격. 최대 80회 위치 후보 시도 후 실패 시 이번 생성은 건너뛰고 다음 틱에 재시도한다(강제 겹침 금지).
- 후보의 60%는 기존 도형 주변 65~125px 내 군집, 40%는 균일 난수 분포. 군집 실패 시 균일 분포 재시도.
- 활성 파편의 예상 선분 궤적에서 `도형 반지름 + 15px` 거리 내에는 생성하지 않도록 가급적 회피.
- 새로 등장한 도형은 0.15초 크기 확대로 표시하고 **첫 0.15초는 타격 불가**로 한다(스폰 직후 체인 자동 제거 방지).
- **해금 최초 등장 보장:** 12개 달성 시 Pentagon 1개, 30개 달성 시 Star 1개를 다음 보충 대기열 최우선에 넣는다. 한 연쇄로 두 임계점을 동시에 돌파하면 `Pentagon → Star` 순서로 등장시키고, 나머지는 현재 확률 사용.
- 강화 변종은 도형 종류를 추첨한 후 Enhanced 판정. 새 종류가 별도 단계 화면으로 전환되거나 기존 도형이 사라지지 않는다.
- 대량 연쇄 직후 잠시 빈 공간은 허용하지만 목표 동시 수까지 점진 보충하여 60초 동안 타깃이 고갈되지 않게 한다.

### 6.1 같은 도형 안에서 형태를 다양화 (신규 P0)

**종류 식별을 절대로 희생하지 않는다.** 모든 변종은 같은 HP/공격 방식이며, 한 번 생성된 도형의 외형은 해당 Run 동안 안정적으로 유지한다. RNG 시드에서 형태 속성을 1회 뽑아서 Shape에 저장한다.

| 도형 종류 | 형태 변형 | 초기 범위 | 항상 유지할 시그널 |
|---|---|---|---|
| Triangle | 높고 좁은/넓고 낮은/약간 기울어진 3각형 | 가로·세로 비율 각 `0.85~1.16`, 꼭짓점 거리 흔들림 `±10%` | 꼭짓점 정확히 3개, 청록 외곽선 |
| Square | 정사각형/직사각형/기울어진 사변형 | 가로·세로 비율 `0.82~1.18`, 각 꼭짓점 이동 `±8%` | 변 4개, 분홍 외곽선 |
| Pentagon | 좌우 대칭/길쭉한/불규칙 5각형 | 꼭짓점 반경 `±11%`, 각도 `±6도` | 꼭짓점 5개, 보라 외곽선 |
| Star | 가는 별/통통한 별/약간 불규칙 별 | 안쪽 반경 비율 `0.42~0.58`, 바깥 반경 `±7%` | 5개 돌출 꼭짓점, 금색 외곽선 |

- 기본 크기 반경은 `13~21px` 중 시드 기반 선택. Enhanced는 별도 테두리 두께/이중선으로 구분. 지나치게 작은 도형은 커서 클릭 가능 반경을 최소 16px로 보장.
- 렌더링은 `localVertices`를 1회 생성하여 각 Shape에 저장하고 `rotation`을 적용한다. 시뮬레이션 충돌은 기존 원형 판정을 유지해 빠르게 구현한다.
- 개별 도형의 회전은 최초 1회 결정 후 거의 고정(고유 파편 방향과 반드시 일치). 가벼운 타격 흔들림은 표시 변환에만 적용하여 실제 파편 각도와 불일치하지 않게 한다.
- HP 감소 시 똑같은 깨짐 마스크 대신 `damageSeed`로 2~3개의 균열 선 위치 및 작은 깎임 코너를 결정한다. 메쉬 물리 절단이나 랜덤한 충돌 반경 변경은 금지한다.

### 6.2 색·명도·표면 다양화 (신규 P0)

- **외곽선은 고정된 게임플레이 종류 색**을 유지. 내부 채움은 같은 타입이라도 3가지 팔레트로 변경한다: `matte`(기본 명도), `bright`(+15% 명도), `deep`(-15% 명도). 채도는 `±12%` 범위. 투명도와 코어/내부 선 스타일도 변형한다.
- 도형마다 내부 무늬 `none / inset / split-line / center-core`를 하나 부여한다. 이는 가독성 위주의 얇은 선이며 텍스처 이미지가 필요 없다.
- 밝기 차이만으로 강화 여부를 표시하지 않는다. **Enhanced는 항상 이중 외곽선 + 작은 갑옷 표식**을 표시해 색각 차이에 관계없이 구분 가능하게 한다.
- 내부 해금 단계가 오를수록 배경의 그리드 톤/주변광을 0.4초에 걸쳐 약하게 전환할 수 있지만, 화면 이동·Sector 문구·타이머 정지는 없다.
- 강한 네온은 별형 파괴 등 중요 효과에 집중하고, 평상시 도형은 과도하게 빛나지 않도록 한다. 배경/도형 명도 대비가 낮아져 클릭하기 어려운 팔레트는 폐기한다.

### 6.3 배치 패턴 다양화 — 시각적 레벨 디자인 (신규 P0)

기존의 `60% 군집 / 40% 분산` 룰은 유지하지만, **군집의 모양**을 구체화한다. 별도 단계 화면은 없다.

| 패턴 ID | 배치 모습 | 체감 | 초기 확률 |
|---|---|---|---:|
| `burst_cluster` | 중심 도형 주변에 3~5개, 거리 65~110px | 쉽게 연쇄되는 기본 군집 | 35% |
| `arc` | 휘어진 반원 4~6개, 간격 50~90px | 충격파가 차례로 지나가는 장면 | 25% |
| `bridge` | 작은 군집 2개를 1~2개의 도형이 연결 | 파편이 옆 군집으로 연쇄 확장 | 20% |
| `scattered` | 화면 빈 영역에 1~3개 분산 | 직접 공격이 필요한 숨 고르기 | 20% |

- 패턴을 뽑아도 **기존 겹침 방지·생성 영역·최대 시도 횟수**를 항상 지킨다. 한 패턴에 필요한 공간이 부족하면 작은 군집 또는 균일 생성으로 폴백한다.
- 파편 비행거리 기본 180px을 고려해 군집의 주요 인접 간격을 65~115px 범위로 한다. 멀리 떨어진 형태만 반복 생성해 연쇄가 허공으로 날아가지 않게 한다.
- 증가하는 Tier에 따라 한 번 보충할 때의 군집 밀도/규모를 조금씩 높이고, 별형 등장 후에는 별형 주변의 삼각형/사각형이 최소 2개 있을 확률을 높인다(단, 100% 강제 잭팟은 금지).
- 최초 튜토리얼용 고정 삼각형 연쇄 배치는 v0.6대로 유지. 이후 모든 형상·색·패턴은 seeded RNG로 재현 가능해야 한다.
- **이 기능은 난도·효과를 추가하는 게 아니라 조합의 물리적 가능성과 시각적 변화를 높이기 위한 레벨 디자인**으로 제한한다.

## 7. 재화·영구 성장

### 7.1 Photon 획득

- `실제 제거 HP 1점당 1 Photon` (오버킬 불인정) + `도형 완전 파괴 보너스`.
- 기본 보상 합계: Triangle 8, Square 12, Pentagon 17, Star 49.
- Enhanced는 HP가 원본보다 2 높고, 완전 파괴 보너스만 원본의 1.5배 올림 처리.
- 직접 타격과 연쇄 타격 보상 동일. 한 도형의 HP/파괴 보상은 한 번씩만 인정.
- 프로토타입에서는 별도 콤보 재화 배율 없음. 연쇄는 **많이 파괴해서** 보상을 더 얻는다.
- Run 도중 HUD에는 `runEarned` 표시. 종료 시 `bank += runEarned` **단 한 번** 정산·저장. 새로고침으로 Run을 중단했다면 이번 Run의 미정산 광자는 지급하지 않는다.

### 7.2 분기형 영구 스킬 트리 — 구현 규칙 (신규 필수)

**단순한 세로 목록 대신 실제 연결선이 있는 스킬 그래프**를 만든다. `ROOT`에서 네 방향으로 갈라지는 최소 그래프를 사용하며, 기존 스킬 5종의 동작·가격·최대 레벨을 보존한다. P0는 기존 5개 스킬을 그래프에서 **실제로 구매 가능**해야 하고, P1은 아래 신규 스킬을 추가해 다양한 빌드의 맛을 검증한다.

```text
                             [CORE / ROOT] (자동 해금)
         ┌────────────────┬───────────────────┬────────────────┐
      DESTROY           CASCADE             REACTION         UTILITY
  [Crush Power]      [Shard Power]     [Chain Amplifier]   [Extra Time]
      ├─ [Crush Speed]   ├─ [Shard Range]    └─ [Echo Catalyst] └─ [Photon Boost]
      └─ [Impact Pulse]  │   └─ [Ricochet+]
                        └─ [Shard Bloom]
```

**UI 요건:** SVG 또는 CSS 연결선, 타입별 4개 열, 노드 상태 `locked / available / affordable / purchased / max`, 노드 클릭 시 우측 또는 하단 정보 패널에 현재 효과·다음 효과·가격·선행조건. 선행조건 미충족이면 구매 비활성. 스킬 레벨·재화 변화 후 연결선과 상태 즉시 갱신. PC 960px 화면에서 가로 스크롤이 필요하면 그래프 뷰 영역에 한정하고 결과/재시작 버튼은 항상 접근 가능. 처음에는 드래그 줌/복잡한 인터랙션 불필요.

| ID | 분기 | 효과/레벨 | 첫 가격 | 최대 Lv | 구매 선행조건 | 우선순위 |
|---|---|---|---:|---:|---|---|
| `crushPower` | Destroy | 직접 피해 `3+Lv` | 60 | 5 | 없음 | P0 |
| `shardPower` | Cascade | Triangle/Pentagon 주 파편 피해 `3+Lv` | 90 | 5 | 없음 | P0 |
| `shardRange` | Cascade | 주 파편 최대 거리 `180+50×Lv`px | 70 | 3 | `shardPower >= 1` | P0 |
| `chainAmplifier` | Reaction | Square/Star 피해 `기본+Lv`, 반경 `기본+15×Lv`px | 130 | 3 | 없음 | P0 |
| `extraTime` | Utility | 한 Run `60+5×Lv`초 | 120 | 6 | 없음 | P0 |
| `crushSpeed` | Destroy | 클릭 반복 간격 `max(0.14, 0.20 - 0.02×Lv)`초 | 150 | 3 | `crushPower >= 1` | P1 |
| `impactPulse` | Destroy | **성공적인 직접 타격** 시 반경 42px·피해 1의 실제 추가 충격파 1개 | 260 | 1 | `crushPower >= 2` | P1 |
| `ricochetPlus` | Cascade | 주 파편 벽 반사 허용 횟수 `1+Lv` | 170 | 2 | `shardRange >= 1` | P1 |
| `shardBloom` | Cascade | Triangle 고유 파편 수 `3+Lv`; Pentagon 주 파편 수 `2+Lv` | 290 | 2 | `shardPower >= 2` | P1 |
| `echoCatalyst` | Reaction | 계승 보조 효과 피해 `기본+Lv` | 240 | 2 | `chainAmplifier >= 1` | P1 |
| `photonBoost` | Utility | 완전 파괴 보너스만 `×(1+0.10×Lv)`; 소수점 올림 | 180 | 3 | `extraTime >= 1` | P1 |

- 모든 반복 스킬 비용은 `ceil(baseCost*1.6^currentLevel)`; 최대레벨 후 MAX.
- `impactPulse`에서 클릭 대상 본인은 추가 피해를 다시 받지 않는다. 충격파는 별도 공격 효과로 판정하고 한 대상 최대 1회, 추가 파괴는 해당 클릭의 `chainId` 귀속. 이 타격은 Square의 고유 충격파가 아니므로 Square→Triangle 계승을 일으키지 않는다. 클릭 장식 링과 실제 Pulse 범위를 명확히 구분한다.
- `shardBloom`이 있어도 Pentagon의 소형 파편 분열 개수는 주 파편당 2개로 유지한다.
- 기본 Cross-Reaction은 기존 명세처럼 **초기 활성 + 디버그 ON/OFF**를 유지하므로, `echoCatalyst`는 해금이 아닌 계승 피해 강화다.
- `photonBoost`는 **완전 파괴 추가 보너스에만** 적용하며 실제 제거 HP 1:1 보상에는 적용하지 않는다.
- P1에 앞서 5개 P0 스킬의 구매·적용·저장이 모두 되어 있어야 한다. P1 스킬을 미구현 상태에서 클릭 가능한 가짜 구매 버튼으로 남기지 말 것. 구현 순서상 노드가 준비되지 않았다면 `COMING LATER`로 명시, 구매 불가.

### 7.3 트리 데이터를 선언적으로 관리

하드코딩된 노드별 조건문 대신 `skillDefinitions` 배열에 다음 정보를 둔다. 새로운 노드 하나를 추가해도 기본 그래프 렌더러/구매 코드가 바뀌지 않도록 한다.

```js
{
  id: 'shardRange',
  branch: 'cascade',
  label: 'Shard Range',
  position: { col: 2, row: 2 },
  prerequisites: [{ id: 'shardPower', minLevel: 1 }],
  baseCost: 70,
  maxLevel: 3,
  effectKey: 'shardRange',
  description: '주 파편 사거리 +50px / Lv'
}
```

- `unlock/affordable/max`는 공통 함수로 계산. 순환 선행조건 검사 및 존재하지 않는 노드 참조 검사.
- 기존 `localStorage` v0.6의 `bank`, `levels`, `bestStats`, `lastRuns`는 그대로 마이그레이션해 보존하고 신규 스킬 레벨만 0으로 초기화. `saveVersion` 올리고 테스트 작성.
- 실제 게임 동작은 한 곳의 `getDerivedStats(levels)`로 합성하고, VFX와 스킬 설명은 동일한 도출 수치를 참조한다.

## 8. 시간 / 종료 / 영구 저장

- 첫 Run 시간 60.0초, `extraTime` Lv.2라면 70.0초.
- 초 단위 누적 오차 방지를 위해 게임 실행 중의 단조 시간 delta를 누적하되 탭 비활성화 중에는 delta를 더하지 않는다.
- 남은 시간이 0에 도달하면 게임 입력·공격·스폰·피해 처리 중단. 0초 **이후** 사망한 것처럼 처리하지 않는다. 비주얼 잔상만 최대 0.3초 허용.
- `RESULT+UPGRADES`: Run 총 파괴 수, 직접/연쇄 파괴 수, 최고 Chain, 획득 광자, 이번 Run 최고 Tier, 이전 최고 기록과 비교, **그래프형 스킬 구매**, `Play Again`.
- localStorage에는 `saveVersion`, `bank`, `levels`, `bestStats`, `lastRuns`(최대 20개), 개발자 옵션을 보관한다. v0.6 저장이 존재하면 마이그레이션하여 기존 스킬/재화를 보존한다.
- 저장 데이터가 없거나 손상되었으면 안전한 초기 상태로 시작. 명시적 확인 후 세이브 초기화 가능.
- Run 보상은 **중복 정산 불가**. 종료 버튼을 여러 번 누르거나 RESULT가 두 번 렌더되어도 은행이 한 번만 증가한다.

## 9. Chain 계산 / 안전 제한

- 모든 직접 공격마다 독립된 `chainId` 생성. 직접 공격이 도형을 죽이지 않아도 해당 ID는 존재할 수 있다.
- 이후 발생한 공격 파편·충격파·계승은 부모 `chainId`를 상속한다.
- Chain 크기는 같은 ID가 죽인 도형 수. 클릭 직접 파괴는 `directKills`, 효과로 파괴된 도형은 `cascadeKills`.
- 여러 효과가 동일 도형에 피해를 준다면 **HP를 0으로 만든 마지막 타격**의 `chainId`로 사망을 귀속한다. 한 도형이 여러 Chain에서 중복 카운트되면 안 된다.
- 최고 Chain과 가장 큰 순간의 `+Photon`은 간결한 팝업으로 표시한다.
- 한 파편/충격파의 동일 도형 중복 피해 금지. 사망 이벤트 정확히 1회.
- 안전 상한: 활성 공격 파편 **150**, 체인 깊이 **10**, 한 Chain의 피해 이벤트 **400**. 상한 도달 횟수를 개발자 패널/Run 기록에 남기고 프레임 정지를 방지. 상한에 도달했다고 가짜 파괴·재화를 만들지 않는다.
- 순환 효과는 시간순 우선순위 이벤트 큐로 순차 처리. 활성 효과 배열 순회 중 삭제/추가로 충돌을 건너뛰지 않도록 주의.
- 기존의 순간 범위 피해 처리와 달리, 충격파는 거리별 전파로 **시간차 피해**를 준다. 다중 파동이 겹치면 각 파동의 실제 도달 시점과 도형 사망 플래그에 따라 정확히 판정.
- 디버그에서 `Sequential Propagation ON/OFF` 비교 모드를 제공할 경우 OFF는 범위 즉시 판정의 실험용이며 기본 ON이다. OFF 결과가 기본 룰로 섞이지 않게 테스트 설정에 기록한다.

## 10. 그래픽·소리 — 클릭·순차 연쇄·도형 다양성 우선 (v0.7)

- 외부 에셋 없이 Canvas 다각형·선·파티클. 기본 4종 외곽선 색은 §3 기준. 모양·내부 밝기·패턴은 §6.1~6.2로 생성.
- **클릭 명중:** 0.12초 충격 링, 0.055초 흰 플래시, 도형 스케일 반동, 2~4개 미세 파편, 경량 타격음. 클릭 미스는 작은 희미한 링 0.07초로만 피드백. 스킬 `impactPulse` 없이는 클릭 링이 주변 HP를 깎지 않는다.
- **부분 손상:** 현재 HP 비율과 각 도형 고유 `damageSeed`에 따른 균열/모서리 깎임; 조각 0.2초 안에 소멸.
- **완전 파괴:** 0.15~0.25초 분해, 0.03초 이후 고유 효과 발사; 파편의 실제 비행→접촉, 충격파 확장→접촉, 이어서 다음 파괴가 시간차로 발생.
- Triangle=청록 3방향 빠른 조각, Square=분홍 확산 링, Pentagon=보라 2갈래→작은 분열, Star=금색 빠른 확장 링 및 강조.
- 다량 연쇄 시 **모든 연출이 같은 프레임에 번쩍이지 않도록** 발사 지연·거리 전파를 우선하고, 화면 흔들림/광원 총합을 클램프한다. 파편 공격은 실제 판정 후 사라지되 0.1초 미만 잔상은 허용.
- 타격이 큰 순간에는 클릭·연쇄 시작의 효과음 피치를 조금씩 증가시켜 진행감을 만든다. 오디오가 겹칠 경우 짧게 믹싱·쿨다운하여 소리 폭주 방지. Web Audio 합성, 음소거 토글, 외부 리소스 없음.
- VFX 오브젝트 풀/배치 렌더링을 사용할 수 있지만, 렌더링 입자가 줄어도 피해·보상은 누락되면 안 된다.
- 개발 옵션 `Damage VFX`, `Sequential Propagation`, `Visual Variety`, `Inheritance`, `Ricochet`을 독립적으로 비교 가능하게 만든다.

- `requestAnimationFrame`으로 렌더. 시뮬레이션은 fixed timestep(예: 1/60s)과 누적 시간 보정, 최대 catch-up 제한 사용.

- pure 함수 형태의 보상/업그레이드 가격/단계 계산/선분 충돌 등은 `node --test`로 검증 가능하도록 구현하라(필요하면 `package.json`에 `type: module`, `test` 스크립트 정도만 추가).
- `config.js`를 단일 튜닝 위치로 유지하고 상수 복붙 금지.

이 값은 테스트 결과가 아닌 구조 예시다. 실제 수치를 로그에서 생성하라.

## 13. 필수 자동/수동 테스트

1. `crushPower=0`: HP4 Square 직접 피해 3 후 HP1, 다음 클릭에서 정확히 한 번 파괴.
2. `shardPower=1`: Triangle 파편 피해 4로 기본 Square를 일격 파괴. 0레벨에서는 피해 3만 적용.
3. Square 충격파는 범위 안 3개 도형에 각각 최대 한 번씩 정확한 피해 부여.
4. Pentagon 주 파편 충돌 시 **소형 파편 정확히 2개**, 재분열 없음, 직전 타깃 즉시 재피격 없음.
5. 파편 벽 반사 ON/OFF, 총 이동거리 및 동적 수명 제한 준수. `Shard Range` 업그레이드로 실제 최대 이동거리가 증가하는지 검증. 빠른 파편의 통과 방지.
6. 직접 공격 한 번으로 12와 30 파괴 임계값을 동시에 넘으면 신규 종류를 `Pentagon → Star` 순으로 최초 보충.
7. 도형 파괴 후 목표 동시 수로 보충되고 서로 겹치지 않음. 강화 변종이 55회 이전에 생성되지 않음.
8. Inheritance ON: Triangle 고유 파편으로 Square 파괴 시 정확히 작은 바늘 1개 추가. OFF 시 없음. 보조 효과는 재계승 없음.
9. 정해진 seed의 시작 유도 클릭에서 최소 4개 파괴(첫 연쇄 손맛 보장).
10. 보상 계산: Triangle 완전 파괴 총 8, Square 12. 공격 100이 HP3 Triangle에 들어가도 HP 보상은 3만.
11. Extra Time 레벨 0/1/2/6에서 Game 시작 시간이 각각 60/65/70/90초.
12. 시간이 0 이후 추가 공격, 생성, 광자 증가가 없음. 숨김 탭에서는 게임 시간이 멈춤.
13. Run 종료 시 은행 정산 정확히 한 번, 재실행 후 스킬·은행 유지, 실행 중 새로고침한 Run의 미정산 광자 미지급.
14. 긴 연쇄·동시 파괴 테스트에서 중복 보상, 무한 생성, 멈춤, 콘솔 오류가 없음.
15. 업그레이드 구매 비용·레벨·MAX·잔고 부족 버튼 동작이 정확함.
16. 960×540 논리 좌표에서 브라우저 크기 변경 후에도 클릭 위치가 정확함.
17. Square 충격파에서 중심 30px의 A와 중심 80px의 B가 있을 때, A가 먼저 피해를 받고 이후 B가 피해를 받음. Square 생성 순간 B는 아직 HP 유지.
18. Star 폭발 반경 145px 중 120px 대상의 피해는 확산 속도 720px/s 도달 전에는 발생하지 않음.
19. Triangle 파편으로 도형을 파괴한 후 후속 효과는 0.03초 지연 발사되며, 다른 도형에 명중한 후에는 다음 파괴가 실제 시점에 이어짐.
20. 클릭 명중과 빈 공간 클릭 모두 즉시 VFX가 보여야 하지만, 기본 클릭 장식 링은 도형 주변에 추가 피해를 주지 않음.
21. seeded RNG가 같으면 각 종류의 폴리곤 꼭짓점·색상 밝기·표면 무늬·패턴이 동일하게 재현됨. `Visual Variety OFF`에서도 HP·파편 공격 결과가 동일함.
22. Enhanced는 외형 색상과 무관하게 이중 외곽선으로 식별되고 HP가 정확히 원본+2. 코스메틱 명도·모양 변형은 HP를 바꾸지 않음.
23. 스킬 트리 노드/엣지가 선행조건을 정확히 반영하고, 잠긴 노드는 구매되지 않음. 가격/MAX/레벨 저장이 정상. P1 미구현 노드는 구매 불가 상태를 명확히 표시.
24. 기존 v0.6 save를 로드했을 때 은행, 5개 기존 스킬 레벨, 최고 기록이 보존되고 새 스킬 레벨만 0으로 추가됨.
25. `impactPulse` 구매 전 클릭 반응은 무피해, 구매 후 성공 클릭 시 한 번만 주변 피해. 다른 고유 효과의 계승 원인으로 오인하지 않음.
26. 60초 종료 직전 예약된 파동이 시간 종료 후 도달한 경우 해당 피해·재화·파괴 수는 증가하지 않음.
27. 같은 사망 시점에 여러 파동이 중첩되어도 도형 파괴·보상은 정확히 한 번.
28. 100개 이상 도형 연쇄에 가까운 부하 조건에서 렌더링·스케줄링이 멈추지 않으며 안전 상한 도달 여부가 기록됨.

## 14. 구현 순서와 우선순위 — 기존 v0.6 코드가 있는 경우

**새 프로젝트가 아니라면 기존 프로토타입부터 실제로 실행·점검하고, 게임 동작 및 세이브를 보존한 채 아래 순서로 수정한다. 각 마일스톤 후 실행 가능 상태를 유지한다.**

1. **P0-1:** 기존 코드 진단: Square/Star의 전역 즉시 피해 구조, VFX 생성 위치, 기존 Upgrade UI/Save 구조를 확인하고 README에 변경 계획을 짧게 정리.
2. **P0-2:** 즉각적인 클릭 타격 VFX(명중·실패 구분) 구현. HP/재화에는 영향이 없는지 검증.
3. **P0-3:** Square/Star의 확산형 실제 충격파 피해 판정 및 사망 후 효과 +0.03초 예약. 순차 폭발이 실제로 보이고 타이머 종료 이후 판정이 없는지 검증.
4. **P0-4:** 절차적 다각형 기하(동종 형태 변종), 밝기/채도/코어 무늬, 군집 패턴 4종 추가. 가독성·클릭 영역·물리 충돌 불변 검증.
5. **P0-5:** 기존 스킬 5개를 SVG 연결선을 가진 데이터 기반 트리 UI로 옮기고, 동일한 비용·레벨·시간 증가·구매/저장 동작 보존.
6. **P1-1:** 신규 실제 스킬(크러시 속도·클릭 Pulse·반사 증가·분열 확장·계승 강화·Photon 보너스)을 트리 노드로 추가. 선행조건/비용/파생 스탯 테스트.
7. **P1-2:** 디버그 비교 토글, 이벤트 전파/체인 지표, 저장 마이그레이션, 자동/브라우저 QA, 실제 실행 스크린샷.
8. **P2:** 필요한 만큼만 오디오 피치·이펙트 최적화. 외부 이미지 제작, 수십 종류 도형 추가, 정식 게임 수준의 아트/상점은 금지.

우선순위는 **P0 클릭 감각 + 순차 폭발 + 변종 도형 + 최소 노드 그래프**다. 신규 스킬 6종은 기존 5개를 그래프로 이전한 뒤 추가해도 된다. 구현되지 않은 P1 노드에는 결제 동작을 만들지 말 것.

## 15. 재미 검증 기준 (출시 승인 기준이 아님)

실제로 3~5회 Run을 반복하며 다음 질문을 관찰한다.

- 첫 3초 안에 도형을 직접 깨는 손맛이 전달되는가?
- 첫 10초 안에 연쇄 파괴를 경험할 수 있는가?
- 60초가 지루하지 않고 새 도형/밀도 변화가 자연스럽게 나타나는가?
- 직접 클릭과 파편 자동 연쇄의 기여가 모두 의미 있는가?
- `Shard Power +1`과 `Crush Power +1`에서 **파괴 임계점 변화**가 체감되는가?
- 연쇄가 한꺼번에 터질 때보다 시간차로 퍼질 때 인과관계가 더 잘 보이고 더 재미있는가?
- 코스메틱 도형 변종과 배치 패턴이 단조로움을 줄이면서도 도형 종류를 헷갈리지 않게 하는가?
- 스킬 트리의 다음 노드/가지가 보이면 한 판 더 플레이하고 싶은 동기가 생기는가?
- 계승/반사 ON/OFF가 실제 재미에 기여하는가?
- Game Over 후 스킬을 구매하고 자발적으로 다시 시작하고 싶은가?

초기 관찰 목표: 연쇄 킬 비율 25~60%, 첫 Run 종료 후 스킬 1개 이상 구매 가능, 첫 Run에서 Pentagon 및 가능하면 Star 발견. 이는 밸런싱의 실험 가설이지 구현을 위해 숨겨진 보정을 넣으라는 의미가 아니다.

## 16. Codex 구현·검수 세부 지시 (v0.7)

- 시작 전에 현재 저장소의 실제 구조·구현 상태·README·테스트를 확인하고 v0.6 대비 빠진 기능/충돌사항을 목록화한다. 기존 기능이 동작한다면 재작성 대신 국소 수정한다.
- 상태/전투 로직과 렌더링을 분리한다. `requestAnimationFrame` 안에서 UI 효과 때문에 60초 게임 타이머가 일시정지되거나 히트 판정이 미뤄지는 일이 없어야 한다.
- **순차적 전파는 게임플레이 규칙**이다. 단순 UI setTimeout으로 데미지 로직을 지연시키지 말고 시뮬레이션 게임 시간과 이벤트 큐로 관리한다.
- Shape 생성 시 게임플레이 데이터와 코스메틱 외형 seed를 분리한다. `Visual Variety OFF`가 보상/공격/배치를 바꾸면 안 된다.
- 스킬 트리는 신규 노드를 추가할 때 DOM 마크업과 구매 조건을 곳곳에 수정할 필요가 없도록 공통 데이터 렌더러로 구현한다.
- P0 개선 완료 후 브라우저에서 60초 Run → 결과 화면 → 스킬 구매 → 다음 Run을 최소 두 번 실행해 눈으로 점검하고, 가능하면 스크린샷을 남긴다.
- 설명이나 PRD만 쓰고 종료하지 말고 **실제 작동하는 코드와 테스트 결과**를 낸다. 외부 이미지·폰트·백엔드·엔진은 추가하지 않는다.

**최종 완료 보고 형식:** 구현 기능 요약, 실제 실행 방법, 테스트 통과/실패 내역, 스크린샷 경로(가능 시), 미구현·알려진 문제, 가장 먼저 조정할 밸런스 파라미터 5개. 정식 게임 제작 여부는 플레이 테스트 후 결정한다.
