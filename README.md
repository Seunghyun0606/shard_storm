# Shard Storm — playable prototype v0.6

`docs/Shard_Storm_Codex_Prototype_PRD_v0.6.md` 전체를 구현 기준으로 사용한 재미 검증용 프로토타입입니다. HTML5 Canvas 2D + Vanilla JavaScript ES Modules로 동작하며 게임 엔진, 외부 이미지, 런타임 패키지, 번들러, 서버 저장을 사용하지 않습니다.

## 실행

이 폴더에서 Node.js 20 이상으로 실행하세요. 의존성 설치는 필요 없습니다.

```powershell
npm start
```

브라우저에서 **http://127.0.0.1:4173** 를 열고 `START RUN`을 누르세요. 종료는 서버 터미널에서 `Ctrl+C`입니다. 다른 포트는 `$env:PORT = '4174'; npm start`로 지정할 수 있습니다. ES Modules를 사용하므로 `index.html`을 `file://`로 직접 열지 마세요. Python이 있으면 `python -m http.server 4173 --bind 127.0.0.1`도 사용할 수 있습니다. 저장은 프로토콜·호스트·포트별 localStorage이므로 주소를 바꾸면 별도 저장으로 취급됩니다.

## 플레이

- 청록색 안내가 있는 중앙 Triangle을 클릭하면 첫 연쇄를 경험합니다.
- 좌클릭은 도형 1개에 즉시 피해, 누른 채 드래그하면 0.20초마다 반복 공격합니다. 빈 공간은 공격하지 않습니다.
- 첫 판은 60초이며 누적 파괴 수 12/30/55/90/140에 따라 도형 종류·강화 변종·밀도가 증가합니다. 중간 시간 초기화나 화면 이동은 없습니다.
- Triangle: 표시된 꼭짓점 방향 3개 파편. Square: 분홍 충격파. Pentagon: 보라색 주 파편 2개, 첫 충돌마다 소형 2개 분열. Star: 금색 광역 폭발.
- Game Over에서 실제 HP 제거와 파괴 보너스로 얻은 Photon을 은행에 한 번만 정산합니다. 5종 스킬을 구매한 뒤 `PLAY AGAIN`으로 반복 플레이합니다.
- 강화는 다음 판에 반영됩니다. Extra Time을 구매하면 65~90초로 늘어납니다. 같은 60초 성능 비교에는 Extra Time을 구매하지 마세요.
- 탭 비활성화 시 자동 일시정지, 수동 일시정지도 가능합니다. 마우스 버튼 해제·아레나 이탈·창 포커스 상실 시 홀드가 중지됩니다.
- `SOUND`는 선택적인 Web Audio 합성음입니다. 기본 OFF입니다.

## 개발자 패널

`D` 또는 `DEV [D]`로 열며 기본 숨김입니다.

- **Inheritance**: Triangle 고유 파편→Square의 바늘, Square 고유 충격파→Triangle의 작은 충격파. 보조 효과 자체는 재계승하지 않습니다.
- **Ricochet**: 주 파편의 벽 반사 1회 ON/OFF. 거리·수명은 반사 후에도 누적됩니다.
- Damage VFX / Sound ON/OFF.
- 실시간 시간·파괴·연쇄·은행·Tier·개체 수·파편 수·평균 FPS·안전 상한 횟수·시드 확인.
- 같은 시드 새 판, 다음 판 테스트 시간 지정, 종류별 강제 생성, 테스트 Photon 지급, 실제 Run JSON 복사, 확인 후 세이브 초기화.

`동일 Seed 새 Run`은 진행 중 미정산 판을 폐기합니다. 강제 생성과 테스트 지급은 일반 플레이 기록과 구분해서 사용하세요. 재미를 비교할 때는 시드·강화·시간·입력 정책을 같게 두고 토글만 바꾸세요. 도중 토글 변경은 Run의 `optionChanges`에 기록됩니다.

## 구현 범위와 파일

P0와 P1의 게임 기능을 구현했습니다. P2 중 수동 일시정지와 선택적 합성 사운드를 포함했습니다.

| 파일 | 역할 |
|---|---|
| `config.js` | 게임 수치, 업그레이드, 해금 표, 안전 상한, 기본 옵션 |
| `game.js` | 순차 피해 큐, 연쇄, 시간, 군집 생성, 파편 이동·반사 |
| `entities.js` / `effects.js` | 시드 난수, 도형, 좌표 변환, 선분 충돌, 파편 수치 |
| `progression.js` / `storage.js` | 가격·구매, 1회 정산, 저장·손상 복구 |
| `renderer.js` / `app.js` | Canvas 시각 효과 / DOM·입력·개발자 패널 |
| `server.js` | 의존성 없는 로컬 정적 서버 |
| `tests/` | PRD 규칙 테스트, 반복 시뮬레이션, 실제 브라우저 QA |

판정은 원형 히트영역 기준이며 시각적 균열·모서리 깎임·넉백은 판정과 분리됩니다. 충격파 범위는 도형 중심 거리 기준입니다. 공격 파편은 이전→다음 위치의 선분 충돌로 가장 먼저 맞은 도형만 타격합니다. 물리 시뮬레이션은 1/60초 고정 스텝, 프레임당 최대 8스텝이며 화면이 활성인 긴 지연에서는 밀린 물리를 생략하되 실제 제한시간을 소비합니다. 따라서 느린 기기에서 판 시간이 늘어나지 않습니다. 비활성 탭 시간은 소비하지 않습니다.

시각 난수와 게임 난수를 분리해 VFX 토글이 배치·보상을 바꾸지 않습니다. 사망 표시 후 보상·효과를 처리하며 모든 연쇄는 마지막 치명타의 ID에 귀속됩니다. 활성 파편 150개, 깊이 10, Chain당 피해 이벤트 400개를 넘으면 실제 후속 이벤트를 중단하고 횟수만 기록합니다. 가짜 보상은 없습니다. 비활성 Chain과 소멸 도형·파편·장식은 정리합니다.

## 테스트 실행

```powershell
npm test
npm run benchmark
```

- `npm test`: PRD 필수 16항목의 로직을 26개 테스트로 검사합니다. 브라우저 UI·탭 비활성화는 아래 브라우저 QA와 별도 단위 테스트로 검사합니다.
- `npm run benchmark`: 동일 시드 기본/강화 60초 비교, 계승 OFF/반사 OFF 비교, 다른 시드 12판 스트레스 테스트. `artifacts/simulation-results.json`에 실제 결과를 저장합니다.
- 모든 시뮬레이션은 가상 시간을 사용하며 자동 타깃 선정 정책입니다. 사람의 재미 평가나 실제 렌더링 FPS 측정으로 해석하지 않습니다.

실제 브라우저 QA 도구 Playwright는 게임 런타임에 포함되지 않습니다. 별도의 임시 폴더에 설치하고 로컬 서버를 실행한 채 다음을 실행합니다. Chromium 기반 Chrome이 설치되어 있어야 하며 필요하면 `CHROME_PATH` 환경변수에 실행 파일 경로를 넣으세요.

```powershell
$qaPath = Join-Path $env:TEMP 'shard-storm-qa'
npm install --prefix $qaPath playwright --no-audit --no-fund
$env:PLAYWRIGHT_MODULE = Join-Path $qaPath 'node_modules/playwright'
node tests/browser-check.mjs
node tests/visibility-check.mjs
```

이 도구는 테스트용 브라우저의 저장을 초기화하고 실제 포인터 입력으로 기본·강화·계승/반사 OFF 60초 판을 진행합니다. 구매·새로고침·재플레이·MAX·잔고 부족·좌표 리사이즈·콘솔 오류도 확인합니다. `artifacts/browser-results.json`과 PNG 스크린샷을 생성합니다. 일반 사용자의 기존 브라우저 프로필은 사용하지 않습니다.

## 알려진 한계와 추후 후보

- **사람이 느끼는 재미는 아직 검증하지 않았습니다.** 자동 입력 결과와 사람의 마우스 숙련도는 다릅니다. 3~5판 사람 플레이에서 첫 파괴/연쇄 경험, 다시 하고 싶은 정도, 토글 선호를 관찰해야 합니다.
- 최적화된 자동 공격에서 연쇄 비율은 기본 약 62%, 강화 약 73%로 PRD 관찰 목표 25~60%보다 높습니다. Photon도 많이 쌓여 강화가 빠릅니다. 지정 수치는 임의로 바꾸지 않았습니다.
- 동일 시드에서 계승 또는 반사를 끈 결과가 더 높은 경우가 있습니다. 추가 피해가 마지막 치명타·다음 배치·난수 소비 순서를 바꾸므로 점수는 단조 증가하지 않습니다. 여러 시드/사람 입력에서 비교해야 합니다.
- 실시간 브라우저 자동 입력은 프레임·마우스 이동 시점 차이 때문에 동일 시드에서도 점수가 다를 수 있습니다. 정확한 재현 비교는 고정 시간/입력 정책의 `npm run benchmark`를 사용하세요.
- 상한 도달 시 후속 피해가 잘릴 수 있으므로 최대 강화의 연쇄 크기가 제한됩니다. 안전장치를 제거하기보다 후속 밸런스 실험을 먼저 권장합니다.
- 넉백은 시각적 연출만 적용하고 실제 히트영역 중심은 고정합니다. 도형 간 충돌 피해와 실제 폴리곤 절단은 명세상 제외입니다.
- 손상 조각을 끄더라도 필수 파편·충격파 링은 표시합니다. 사운드는 파괴 시 합성음이며 직접 타격 전용 별도 음색과 화면 흔들림은 추가 후보입니다.
- 모바일 최적화, 보스, 로그인, 서버, 온라인 기록 등은 구현 범위 밖입니다. 작은 모바일 화면의 상점 사용성을 보장하지 않습니다.
- 저장이 차단되거나 용량이 부족하면 화면에 알리고 현재 세션에서만 유지됩니다. 새로고침 중 미정산 Run은 지급하지 않습니다.

## 먼저 조정할 밸런스 파라미터 5개

모든 게임 밸런스 수정은 `config.js`에서 합니다. 수치를 변경하면 기본 테스트의 PRD 기대값도 함께 검토하세요.

1. **`shapes.*.hp` / `shapes.*.shardDamage`**: 일격 파괴 임계점, `Shard Power +1`의 체감.
2. **`shard.range` / `shard.rangePerLevel`**: 기본 연쇄 도달 거리와 성장 규모.
3. **`shapes.square.areaDamage/areaRadius` / `shapes.star.areaDamage/areaRadius` / `amplifierRadius`**: 광역 연쇄 규모.
4. **`tiers[].target/weights/enhanced` / `clusterChance/clusterMin/clusterMax`**: 타깃 밀도, 군집, 신규 도형 발견 속도.
5. **`upgrades.*.baseCost` / `costGrowth`**: 첫 판 구매 수와 반복 플레이 성장 속도.

추가 비교 변수는 `attackInterval`, `inheritance.radius/damage`, `options.ricochet/inheritance`, `caps.depth/events`입니다. 출시 여부 결정 전에 사람 플레이 결과로 조정하세요.
